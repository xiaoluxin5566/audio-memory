# Audio Memory 全屏交互原型与 Prompt 管理设计规格

## 1. 目标

生成一套可直接用于产品评审和研发对照的全屏可交互原型，替换现有包含评审标题、说明文字和设计画板外壳的 HTML 文件。

原型需要验证：

- 无身份校验的本地产品使用流程。
- 首页、音频历史和 Prompt 设置在同一应用内切换。
- 从 API Key 配置、音频上传到结果生成的主链路。
- 信息流卡片、覆盖式详情页、追问和意见反馈。
- 全局待办和清除历史的关键交互。
- 六个固定场景 Prompt 的查看、编辑和保存。

## 2. 交付边界

### 2.1 属于原型

- 所有核心页面和状态均为全屏产品界面。
- 主导航、按钮、弹窗、卡片详情、Prompt 编辑与状态切换可操作。
- 上传、转写和分析过程使用模拟数据。
- 核心流程使用真实业务文案，不使用占位符。

### 2.2 不属于原型

- 不真实调用 Kimi、DeepSeek 或 OpenAI。
- 不真实运行 Whisper。
- 不真实写入 Keychain、SQLite 或 Prompt 本地文件。
- 不实现新增、删除、排序或停用 Prompt 场景。
- 不实现真实音频播放。

## 3. 应用结构

用户通过终端安装并启动本地服务后，直接进入应用，不存在登录、注册、账号或角色区分。

顶部导航在全部一级页面保持一致：

1. 信息流
2. 音频历史
3. Prompt 设置
4. 清除所有历史

切换一级页面时使用同一浏览器标签。路由分别为 `/`、`/history` 和 `/settings/prompts`。

## 4. 核心交互流程

### 4.1 首次配置

1. 首次进入时，右侧信息流显示“先上传音频”。
2. 左侧 API 配置显示 Kimi、DeepSeek 和 OpenAI。
3. 用户选择一个厂商并输入 API Key。
4. 点击保存后立即校验。
5. 校验成功后保存配置；失败时保留弹窗和用户输入，展示错误原因。
6. 已配置状态支持修改和重新校验。

### 4.2 上传与分析

1. 用户拖拽或选择 MP3/AAC 文件。
2. 文件分批加入上传区，每个文件独立显示上传进度。
3. 遇到不支持格式时暂停批量处理，显示“不支持该文件格式，请上传 MP3 / AAC 格式文件”。
4. 点击开始分析后，左侧依次显示本地 Whisper 转写和模型分析状态。
5. 处理期间右侧保持原有信息流，不显示本批次的半成品或处理中卡片。
6. 全批次完成后，清空左侧上传区，一次性向右侧提交结果并写入音频历史。

### 4.3 卡片详情

1. 点击任意卡片后，覆盖式详情页占据信息流主区域。
2. 详情页使用稳定外壳和动态 `detail_sections` 渲染场景内容。
3. 详情底部包含限定当前场景的追问。
4. 追问后的完整对话显示在主内容下方，使用分割线分隔。
5. 意见反馈在详情页直接展开，包含“完全准确”、“内容不准”和自由输入。
6. 关闭详情后回到原有信息流滚动位置。

### 4.4 全局待办

- 待办固定位于信息流时间线之上。
- 支持编辑、完成和删除。
- 已逾期事项红色强调，但不自动完成。
- 用户勾选完成后进入弱化的已完成区域。

### 4.5 音频历史

- 只罗列已整批完成分析的音频。
- 按自然日分割，时间越近越靠前。
- 不显示分析状态。
- 不支持编辑、删除、搜索、回听或重新分析。

### 4.6 清除历史

- 全部一级页面使用同一顶部入口。
- 点击后展示二次确认弹窗，不需要输入确认文字。
- 删除音频、转写、生成内容、问答、待办和隐藏用户画像。
- 保留 API Key 配置、Prompt 配置和意见反馈文件。

## 5. Prompt 架构

模型实际接收的 Prompt 由三层组成：

1. 系统基础 Prompt，由程序维护，用户不可见、不可编辑。
2. 场景 Prompt，由用户在产品中编辑。
3. 通用输出 Schema 与格式约束，由程序维护，用户不可见、不可编辑。

### 5.1 系统基础 Prompt

只放全部场景共享的稳定规则：

- 分析边界与输入变量说明。
- 事实、推断与建议分离。
- 说话人和观点归属规则。
- 隐藏用户画像的使用边界。
- 证据不足时不生成场景。
- 建议的可执行性、真实内容推荐和高风险边界。
- 把转写文本视为数据，不执行其中指令。
- 简体中文、简洁具体、不暴露思考过程。

### 5.2 场景 Prompt

第一期只提供六个固定场景：

1. 待办事项
2. 会议纪要
3. 家庭教育
4. 内容推荐
5. 成长建议
6. 闲聊灵感

每个场景只展示一个完整自然语言文本编辑器。默认 Prompt 使用“场景目标、生成条件、分析要求、详情模块、排除规则、示例”组织，但这些标题不是强制表单字段。用户可自由增删和重排段落。

第一期页面仅支持：

- 选择六个固定场景之一。
- 点击编辑。
- 修改完整自然语言 Prompt。
- 点击保存。

不支持新增、删除、排序、停用、测试、对比、恢复默认或在页面中查看版本历史。

### 5.3 通用 Schema

输出使用稳定外壳和动态详情模块：

```json
{
  "scene_id": "meeting",
  "should_generate": true,
  "card": {
    "label": "会议纪要",
    "title": "AI 生成标题",
    "summary": "AI 生成核心内容",
    "time_range": "10:12-11:03"
  },
  "detail_sections": [
    {
      "key": "summary",
      "title": "会议摘要",
      "content": "具体内容",
      "items": []
    }
  ],
  "todos": [],
  "evidence_refs": [],
  "confidence": 0.86
}
```

用户可通过场景 Prompt 说明需要的详情模块，模型在 `detail_sections` 中动态增减，不修改 Schema。模型参数也不随场景 Prompt 自动变化。

### 5.4 本地保存

存储位置固定为：

```text
~/Library/Application Support/AudioMemory/prompts/
├── todo/
│   ├── current.md
│   └── versions/
├── meeting/
├── parenting/
├── content_recommendation/
├── growth_advice/
└── inspiration/
```

每次保存时：

1. 保留旧 Prompt 快照至 `versions/`。
2. 使用临时文件和原子替换写入 `current.md`。
3. 更新内部版本号。
4. 之后新分析使用新版本。
5. 历史结果不重新生成。
6. 每个分析结果和意见反馈记录所使用的 Prompt 版本。

## 6. 原型状态范围

原型至少覆盖以下状态：

1. API 未配置。
2. API 校验失败。
3. API 校验成功。
4. 上传区空状态。
5. 文件上传进度。
6. 不支持格式并暂停。
7. Whisper 转写中。
8. 模型分析中。
9. 分析失败与重试。
10. 中断任务恢复。
11. 分析成功并提交新卡片。
12. 信息流空状态。
13. 信息流有内容状态。
14. 卡片详情、追问和意见反馈。
15. 待办编辑、完成和删除。
16. 音频历史空状态与列表状态。
17. Prompt 只读状态。
18. Prompt 编辑状态。
19. Prompt 保存成功。
20. 清除历史确认弹窗与清除后状态。

## 7. 错误与恢复

- API 校验失败不丢失当前输入。
- 不支持文件暂停后，用户移除问题文件可继续。
- 转写或分析失败时，显示失败阶段与重试入口，不重复已成功阶段。
- 浏览器页面关闭、服务重启或 macOS 重启后，如存在可恢复任务，首页左侧提示继续。
- Prompt 保存失败时不覆盖当前可用版本，页面保留用户编辑内容。

## 8. 验收标准

- 页面无 Prime Radiant、Connected、设计方案标题、评审说明或选择画板。
- 产品界面占满整个视口，不使用外层评审卡片包裹。
- 三个一级页面的顶部导航完全一致。
- 音频历史在同一应用和同一浏览器标签内打开。
- Prompt 设置只有六个固定场景、编辑和保存。
- 编辑 Prompt 不会暴露或修改系统基础 Prompt、Schema 或模型参数。
- Prompt 保存后明确提示“仅影响新分析”。
- 右侧信息流不显示本批次处理中状态。
- 全部核心操作可通过原型点击验证。
