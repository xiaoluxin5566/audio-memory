# Beta 6 火山云端 ASR 链路设计

## 1. 定位与范围

本设计是 Audio Memory Beta 6 的一个独立功能模块，不代表 Beta 6 的全部范围。它只改变“新上传音频如何生成逐字稿”，报告分析继续复用 Beta 5 已发布的正式报告链路。

目标链路：

`配置分析 API + 配置火山语音 API → 上传 MP3/AAC → 点击开始分析 → 火山云端转写 → 正式报告分析 → 发布报告`

用户只需在开始前完成配置和点击一次“开始分析”，转写成功后自动进入分析，不再要求中途确认。

### 本期包含

- 只接入火山引擎作为新上传任务的语音 ASR。
- 用户配置一个火山 API Key；产品固定使用资源 ID `volc.seedasr.auc`。
- 上传前同时校验分析 API 与火山语音 API，任一不可用则不发送文件字节。
- 只接受 MP3、AAC。
- 单文件原生直传，不转码、不切分；超过火山单文件约束时在上传前拒绝并提示用户拆分。
- 转写和分析均为“首次调用 + 最多 2 次自动重试”。
- 失败后从最近确认成功的检查点继续，已成功部分不重复调用。
- 页面关闭、服务退出、电脑休眠、关机或重启后的可恢复任务。
- 防休眠开关和中断说明交互。

### 本期不包含

- 阿里云 ASR、用户自选 ASR 厂商或自选火山 ASR 模型。
- 用户配置火山 TOS；产品不得要求 TOS bucket、地域或临时授权。
- 视频上传、WAV/M4A/OGG 等其他格式。
- 产品自有云端任务服务器。
- 对既有历史逐字稿批量重新转写。
- 自动切分、重叠区合并和二次编码。
- 删除本地转写备用能力；本地能力可保留在代码中用于开发诊断，但不出现在 Beta 6 新上传主链路。

## 2. 配置模型

分析模型与语音识别是两类独立配置：

- 分析 API：沿用 Beta 5 的分析厂商、模型选择、Keychain 保存与激活逻辑。
- 语音 API：新增单一 `volcano` 配置，只保存 API Key，不显示模型选择，不与分析厂商的 active provider 混用。

火山 API Key 存放在当前运行环境对应的 macOS Keychain namespace 中。ASR 公共接口使用中性命名 `AsrProvider`、`AsrCredentialCoordinator`，本期唯一 provider 值为 `volcano`；资源 ID 是该 provider 的固定配置参数。开发环境必须继续使用开发 Keychain service、开发数据库、开发数据目录和开发端口；不得读取或覆盖正式环境密钥。

ASR 配置状态统一为：

- `unconfigured`：未配置。
- `validating`：正在校验。
- `available`：已验证可用。
- `unavailable`：认证、权限、余额、服务开通或网络校验失败。
- `keychain_unavailable`：本机钥匙串不可用。

保存时立即校验。若官方没有不产生识别任务的独立认证接口，使用产品内置的极短音频执行一次真实校验，并在界面说明该校验可能产生极少量识别用量。上传门禁默认只读取本地缓存状态；仅在状态为 `unavailable`、尚未验证或距离上次验证超过配置的有效期时主动远程校验。只有分析 API 和 ASR API 均为 `available` 才允许创建上传任务并发送文件字节。

## 3. 上传门禁与文件约束

用户拖拽或选择文件后，前端先读取统一 readiness：

- 分析 API 不可用：打开分析 API 配置并说明“请先配置可用的分析 API”。
- 火山 ASR 不可用：打开语音 API 配置并说明“请先配置火山语音 API”。
- 两者都不可用：配置页同时标记两项未完成。
- 两者都可用：才创建 job 并开始上传。

后端同样执行硬门禁，不能只相信前端。`POST /api/jobs` 和 `POST /api/jobs/{id}/files` 在 readiness 不满足时返回结构化 `configuration_required`，且文件端点必须在读取 request body 前拒绝。

格式规则：

- 文件扩展名与探测结果必须为 MP3 或 AAC。
- 单文件必须小于 5 小时且小于 512MB；限制值集中在后端 provider 配置中，前端读取后端返回值展示。
- 满足约束时按原文件提交，不改变采样率、码率、声道或容器。
- 超过任一约束时在发送文件字节前返回 `file_exceeds_asr_limit`，提示用户先拆分音频；Beta 6 不自动切分。

## 4. 云端 ASR 执行模型

每个上传文件生成一个持久化 ASR 文件任务。文件任务至少保存：

- `job_id`、`job_file_id`、文件顺序。
- 相对于运行环境数据根目录的文件引用和内容哈希；不得持久化绝对路径。
- 火山 task ID。
- 状态：`pending/submitted/submission_unknown/polling/completed/retry_wait/failed`。
- 已确认尝试次数、下一次重试时间和稳定错误码。
- 返回结果快照与落库完成标记。

执行步骤：

1. 验证文件格式、时长、大小和本地文件哈希。
2. 对尚未提交的文件调用火山提交接口，并立即持久化 task ID。
3. 轮询已提交 task ID；进程重启后继续轮询同一 ID，不重新提交。
4. 下载并验证结果，转换为现有 `Transcript` 结构。
5. 以 `(job_file_id, segment_index)` 和稳定 segment UID 幂等写入。
6. 所有文件都确认完成后，将 job 推进到 `analyzing` 并提交现有正式分析链路。

一个文件失败不影响已完成文件。只有全部 ASR 成功后才能开始分析，禁止以不完整逐字稿生成报告。

提交请求使用稳定的本地 request ID，但在真实验证前不得把它描述为火山官方幂等键。如果请求可能已到达火山却没有返回 task ID，任务进入 `submission_unknown`：先执行官方支持的查询或等待策略；若无法确认，必须提示用户确认后才能重新提交，不能静默产生重复任务和费用。

## 5. 重试与错误分类

### ASR

每个失败文件任务首次调用后最多自动重试 2 次，采用退避等待。以下错误可重试：

- 网络断开、超时、连接重置。
- HTTP 429 或明确的限流响应。
- 火山服务暂时繁忙、5xx。
- 轮询短暂失败。

以下错误不自动重试：

- API Key 无效或权限不足。
- 服务未开通、资源 ID 不可用。
- 余额或额度不足。
- 文件损坏、格式与声明不符。

自动重试耗尽或遇到不可重试错误后，job 进入可恢复失败状态，展示明确原因与“继续任务”。用户修复配置后点击继续，仅恢复失败文件；已有 task ID、成功结果、逐字稿和本地上传文件全部复用。

ASR 提交队列初始并发数为 2，轮询与提交分别限流。火山 429 使用服务端 `Retry-After`（如有）或指数退避；本地并发等待不计为一次远程失败。

### 分析

正式报告链路中的每个远程调用也是首次调用后最多自动重试 2 次。恢复粒度沿用并补强 Beta 5 检查点：

- 初始报告生成。
- 分区审计；只重试失败分区。
- 审计合并。
- 定向修订。
- 最终审计。
- 发布。

已确认成功的阶段不重复调用。发布必须幂等；若请求返回前进程退出，恢复时先检查持久化结果与发布记录，再决定是否重试。

## 6. 关闭、休眠与恢复语义

产品中的“关闭”必须使用准确表述：

- 关闭当前网页或浏览器标签：后台本地服务仍在运行，任务继续。
- 锁屏但电脑未休眠：任务继续。
- 电脑休眠：网络和本地调度暂停；唤醒后继续。
- 断网：当前步骤暂停或进入退避重试；网络恢复后继续。
- 停止 Audio Memory 后台服务：任务暂停。
- 关机或重启：当前未确认的调用中断；下次启动后从持久化检查点恢复。

启动恢复器扫描 `submitted/submission_unknown/polling/retry_wait` 的 ASR 文件任务，以及未完成分析版本：

- 有火山 task ID：查询原任务。
- 无 task ID 且提交未确认：进入 `submission_unknown`，按前置能力验证确认的官方行为处理；不得假设 request ID 天然幂等。
- 已落库逐字稿：不重复转写。
- 已确认分析检查点：不重复调用。
- 正在调用但结果未确认：允许重试该阶段。

## 7. 用户交互

### 左侧配置区

保留“分析模型与 API Key”，新增独立的“语音转写 API”卡片：

- 固定显示“火山语音”。
- 只填写 API Key。
- 显示未配置、校验中、连接可用和具体失败原因。
- 不展示 TOS、resource ID 或模型选择。

### 开始分析提示

用户点击“开始分析”并成功进入任务后，展示一次说明：

> 分析将在本机后台继续。你可以关闭当前网页，不会影响任务。电脑休眠、关机、断网或停止 Audio Memory 服务会暂停分析；恢复后将从最近完成的步骤继续。建议在任务完成前保持电脑唤醒和网络连接。

只有“知道了”一个按钮。提示不阻断已经启动的任务。

### 防休眠开关

保留 Beta 5 的“分析期间保持电脑唤醒”开关，因为任务仍由本机调度。用户把开关从开改为关时，显示一次提示：

> 请尽量保持开启。电脑自动休眠会暂停转写或分析；唤醒后将从最近完成的步骤继续。

提示只有“知道了”按钮；开关保持关闭，不替用户改回开启。无运行任务时也可修改开关，但只在存在转写或分析任务时显示该提示。

### 进度与失败

任务状态至少区分：

- 正在提交语音转写。
- 云端转写中（文件 X/Y）。
- 正在整理逐字稿。
- 正在生成报告。
- 正在审计/修订/发布。
- 已暂停，可继续。
- 失败，并展示可行动原因。

“继续任务”根据持久化失败点自动路由到 ASR 恢复或分析恢复，用户不需要理解内部阶段。

## 8. 数据、安全与可观测性

- API Key 永不写入 SQLite、日志、错误响应或前端持久化存储。
- 音频会发送至火山语音服务；隐私文案必须从“只有转写文本发送给模型厂商”改为明确区分音频和文本去向。
- 数据库只持久化稳定错误码，不持久化供应商原始错误消息、内部堆栈或绝对路径。前端根据错误码映射中文行动建议。
- 日志只记录 job/file/task 的内部 ID、阶段、耗时、重试次数和脱敏错误码。
- 每次远程调用记录 provider、阶段、开始/结束、结果与尝试次数，用于速度和成本诊断，但不记录 Key 和原始正文。
- 取消任务停止本地轮询与后续分析，不承诺撤销火山已接收的云端任务；上传暂存文件继续使用现有崩溃清理策略。

## 9. 开发与发布边界

- 实施基线是已发布的 `v0.1.0-beta.5`，开发分支命名使用 `codex/` 前缀。
- 编码前必须用开发 Key 完成能力探针：确认是否存在独立认证校验、request ID 重复提交行为、提交后断连时可用的查询能力，以及账号实际 QPS/并发限制。结果写入验收证据；未确认前不得实现乐观幂等假设。
- 必须在新的隔离 worktree 中开发；不得在当前脏工作树上实现。
- 开发环境固定使用开发端口、开发数据根目录和开发 Keychain service。
- 不启动、停止、迁移或写入正式环境；不使用正式数据库和正式 Keychain namespace。
- 完成单元、集成、浏览器端到端和真实火山开发环境冒烟测试后，才可作为 Beta 6 候选功能交付。
- 合并、打标签、构建安装包和推送用户均不在本功能实现的默认授权范围内，需要用户单独确认。

## 10. 验收标准

1. 分析 API 或火山 ASR 任一未配置/不可用时，MP3/AAC 文件字节不会被上传。
2. 两项配置可用后，一次点击可完成云端转写和现有正式报告生成。
3. 用户无需配置 TOS，不需要输入资源 ID 或选择 ASR 模型。
4. 小于 5 小时且小于 512MB 的 MP3/AAC 原文件直传、不转码；超限文件在发送字节前被拒绝。
5. 单个 ASR 文件任务失败最多自动重试 2 次，成功文件不重复提交。
6. 分析阶段调用失败最多自动重试 2 次，从失败检查点继续。
7. 关闭网页不影响任务；休眠、断网、服务退出或重启后任务可从最近确认点恢复。
8. 防休眠开关关闭提示和开始分析说明符合本设计文案及按钮行为。
9. 报告输出继续走 Beta 5 正式链路，未产生第二套报告实现。
10. 开发验证期间正式端口、正式数据库与正式 Keychain 均无写入。
11. 真实验收包含当前四个 MP3、至少一个 AAC，以及超时长和超大小的拒绝测试。
