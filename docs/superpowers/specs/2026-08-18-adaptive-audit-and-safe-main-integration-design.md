# 自适应审计与当日改进安全合并设计

## 目标

将综合报告主链路、按模型能力分块的可恢复审计、转写平滑进度、分析期间防休眠、五分钟 Whisper 物理分块及其块级恢复能力安全合入 `main`。所有合并必须在独立工作树完成，不修改当前运行目录与生产数据。

## 范围

### 纳入

1. `codex/report-audit-revision-pipeline` 中的三段式报告、分段审计、定向修订和终审。
2. 按 provider/model 定义审计输入窗口、输出预留、安全系数和并发数。
3. 审计块被截断时仅二分失败块，持久化成功块并继续运行。
4. 审计覆盖不完整时不得标记整体完成。
5. `codex/smooth-progress` 中的平滑转写进度。
6. `codex/analysis-sleep-prevention` 中的防休眠开关、设置持久化、任务级获取与释放。
7. 已验证的五分钟 Whisper 物理分块、时间戳平移和运行日志。
8. 五分钟物理块内部检查点：保存原始 Whisper 结果，所有块到齐后再统一映射与入库。
9. 当日 UI 修复：显示实际模型名，报告文本生成期间不显示 100%。

### 不纳入

- 本地数据库、API 凭据、真实报告输出、截图和测试缓存。
- 与本次主链路无关的历史实验、日地图、重转写与联网调查。
- 真实付费模型调用和 Keychain 读取。

## 审计模型能力策略

新增独立的模型审计策略对象，输入为 provider ID 和 model ID，输出：上下文 Token 上限、最大输出 Token、输出预留、安全系数、单块最大输入 Token、并发数、最大二分深度和最小块大小。

分块时先计算固定 Prompt、报告正文、Schema 和用户信息的预算，余额才分配给逐字稿。能识别的模型使用显式策略；未识别模型使用保守默认值。估算器必须偏保守，不依赖网络 tokenizer。

## 审计恢复流程

每个审计块拥有稳定 ID，由报告版本、片段起止 ID、模型策略版本和 Prompt 指纹组成。成功结果立即写入 `staged_results_json`。恢复时只复用指纹一致且通过 Schema、证据和覆盖校验的块。

仅对 `model_output_truncated` 执行二分重试。超时和可恢复网络错误重试原块；内容拒绝、认证错误和 Schema 系统错误不通过继续缩块隐藏。达到最大深度后保留所有成功块，任务进入“报告已生成，审计待重试”，不发布虚假的完整审计结论。

所有块成功后，合并器必须校验服务端期望的总片段数、实际审查数和覆盖集合完全一致。

## Whisper 物理块检查点

保留当前固定 300 秒物理块。每块完成后将原始 Whisper 片段、语言结果、物理块索引、音频内容指纹、模型与转写参数指纹原子写入任务 staging 目录。检查点不写入正式 `transcripts` 表。

恢复时只复用指纹和块索引完全匹配的原始结果。全部物理块齐备后，再执行时间戳平移、compact-to-source 映射、边界去重和正式入库。上层 compact checkpoint 格式保持兼容；旧任务没有物理块检查点时从该 batch 开头运行。

任务成功后删除原始块结果。指纹不一致、JSON 损坏或片段缺失时放弃该 batch 的内部检查点并安全重跑。

## 防休眠开关

合并 `codex/analysis-sleep-prevention` 的应用设置、API、前端开关和 macOS 防休眠管理器。默认关闭，用户开启后仅在转写或报告分析任务实际运行时持有防休眠锁。多任务使用引用计数，最后一个任务完成、失败或取消时释放。系统不支持时显示不可用，不影响主流程。

## 合并顺序与冲突策略

1. 审查并合入报告主链路。
2. 以测试驱动方式加入模型策略和可恢复审计。
3. 合入防休眠，重点审查所有退出路径的释放。
4. 合入平滑进度，保留真实检查点作为进度下限。
5. 搬运五分钟物理分块与日志，再以测试驱动方式增加块级检查点。
6. 只挑选当日已确认的 UI 修复，不整体搬运原工作区。

若功能分支同时包含其他历史差异，不直接整分支 cherry-pick，而按文件与行级范围搬运，并为所搬行为补齐测试。

## 测试与验收

- 单元测试：模型策略选择、保守默认、Token 预算、二分终止、稳定块 ID、物理块指纹和损坏恢复。
- 集成测试：审计块部分成功后截断、进程重启复用成功块、完整覆盖后才修订/发布、五分钟块中途恢复。
- 防休眠测试：默认关闭、设置持久化、并发任务引用计数、完成/失败/取消释放、非 macOS 降级。
- 进度测试：页面刷新后恢复、不倒退、不在文本生成期显示 100%。
- 回归测试：完整后端单元/集成测试、前端 Node 测试、Vite 构建和不依赖真实 provider 的端到端恢复测试。

## 完成条件

`main` 仅在以下条件同时满足时更新：集成分支工作树干净；所有定向与回归测试通过；今日改进没有夹带本地产物；审计失败不再标记整体完成；防休眠在所有终止路径释放；旧检查点仍可安全恢复。
