# Beta 8 活动会话索引设计

**日期：** 2026-09-07

## 目标

修复事件索引同时把“正在做什么”、“内容谈到什么”和“应归属哪个报告场景”混在 `kind` 中的问题。索引必须按真实连续活动或联系会话切分，不得按话题切分。

## 核心契约

1. 顶层字段使用 `activity_sessions`，每项代表一次连续真实活动。
2. `activity_kind` 只描述可观察的活动形式：对话、内容播放、独自表达或活动、环境活动、其他。它不做七场景分类。
3. `communication_purpose` 只在 `activity_kind=conversation` 时使用，值为 `work`、`non_work`、`mixed` 或 `uncertain`；非对话活动必须为 `not_applicable`。
4. `participation_mode` 单独表示用户是否亲自实时参与。预录访谈、播客或广播内的问答仍是 `recorded_or_broadcast_content`，不是用户的实时对话。
5. 真实工作沟通必须同时满足 `conversation + user_present_live_interaction + work/mixed`。谈到离职、薪资、年假、职业选择或团队吐槽，不能单凭话题被判为工作目的。
6. 每个活动会话显式记录 `start_boundary` 和 `end_boundary`。同一次会议或电话内的议题变化不建新会话；挂断、散会、前一联系结束后的新问候或身份确认、新联系动作、交互对象或主要活动改变才是新边界。录音文件切换本身不是边界。
7. V1 仍获得完整逐字稿和索引。索引是防漏导航，不是场景判定或写作计划。

## 程序边界

- Schema 强制活动类型、参与方式和沟通目的的合法组合，并要求会话起止字段使用有界枚举；边界证据的语义正确性由 Prompt 和评测门禁检查。普通面对面交谈可以自然开始/结束，不强制伪造电话式接通/挂断信号。
- 覆盖门禁仍只验证每个可靠片段恰好覆盖一次、无缺口、无重叠、引用存在。
- 人工 Ground Truth 仅在评测入口检验真实沟通边界，不传给模型，不修改模型输出，不进入生产默认路径。
- 旧索引检查点因固定规则哈希变更自然失效，不隐式升级或将旧 `kind` 猜测成新字段。

## 验收

- Schema 拒绝旧 `units[].kind=work_communication` 输出。
- 非对话活动不能声称工作沟通目的。
- 媒体播放不能声称用户实时参与；Prompt 禁止使用话题或文件变化作为起止证据，但 Schema 允许面对面活动使用 `activity_started/activity_ended`。
- 非工作对话不进入工作沟通卡闭包；`work` 和 `mixed` 对话必须各自恰好对应一张工作沟通卡。
- 完整覆盖、跨文件会话、有界输出、两次 V1 链路和发布闭包回归通过。
- 不调用付费模型的本地验收只能证明契约与链路修复；对真实输入是否从 21 次改善到 5 次，必须另行获得一次明确付费授权后实测。
