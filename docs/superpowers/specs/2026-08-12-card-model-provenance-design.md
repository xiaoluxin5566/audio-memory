# 卡片生成模型标记设计

## 目标

让信息流中的每张结果卡片（包括“本次概览”）清晰显示实际生成它的模型，便于比较不同模型的输出；历史结果必须保留其分析版本中的真实来源，而不是读取当前配置。

## 数据流

`ContentService.feed()` 已为每张 `Card` 联结对应的 `AnalysisVersion`。扩展卡片 API 视图，增加：

- `provider_id`
- `model_id`

前端规范化时把这两个字段保存在每张展示卡片上，包括严格卡片、兼容旧结构的卡片，以及批次概览卡片。

## 呈现

- 信息流：卡片头部右侧显示紧凑的浅色圆角标签，文案为“厂商名 · 模型名”，例如 `Kimi · kimi-k3`。
- 时间移动至与模型标记同一组，避免挤压左侧的场景标签。
- 详情页：标题上方的场景标签旁显示同款模型标记。
- 本次概览：在概览顶部的 `BATCH OVERVIEW` 标识旁显示模型标记。
- 若极少数旧数据缺少来源字段，则不渲染空标签，不用当前模型误标历史内容。

## 验收

1. `/api/feed` 的每张卡片返回实际分析版本的提供商和模型。
2. 同一批次下卡片与概览均显示标记。
3. 不同历史版本可显示不同模型。
4. 缺失来源字段时页面仍可正常渲染。
5. 后端单元测试和前端测试覆盖字段保留与渲染逻辑。
