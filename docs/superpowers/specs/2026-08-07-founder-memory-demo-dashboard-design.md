# 创始人工作记忆演示看板设计

## 目标

提供一个仅用于向老板演示核心价值的独立网页。它打开即展示一位创始人一周内的工作记忆成果：关键决策、待办、人物洞察和跨录音关联。

该网页只使用内置虚拟数据，不调用真实转写、模型、上传、数据库或生产 API，也不读取或写入现有用户业务数据。

## 演示定位

采用可交互的成果看板，而非完整上传流程。讲解者可先在首页展示整体价值，再按老板的问题打开卡片、待办、人物或录音来源详情。

视觉方向为“高管晨报”：专业、克制、重点结论清晰、信息密度适中。页面固定展示“演示数据”标识，避免被误认为真实用户数据。

## 页面与交互

### 首页总览

- 一周音频时长、提炼记忆数、待办数、重点人物数四项概览。
- 本周趋势与重点主题。
- “今日重点”区：三条可执行的决策、风险或下一步。

### 记忆卡片

- 展示产品决策、客户反馈、商业判断和个人灵感。
- 支持按类型筛选、关键词搜索和日期切换。
- 点击后打开侧边详情：结论、来源录音、时间点、关联待办与人物。

### 待办追踪

- 展示负责人、截止日期、优先级、状态和来源。
- 点击后打开详情，并能跳转到关联记忆卡片和录音时间点。

### 人物洞察

- 展示关键人物、近期互动、关注点、承诺事项与待跟进内容。
- 点击后打开人物详情，列出其相关卡片和待办。

### 录音来源与跨录音关联

- 列出数段模拟会议，显示名称、日期、时长、类型及分析产出。
- 不提供完整逐字稿；仅在详情中显示有限的“来源摘要”和时间点。
- 一个关联视图将客户反馈、内部决策和后续待办串成可点击的链路。

## 虚拟数据与隔离边界

- 虚拟数据存放在演示页专用的前端数据模块中，运行时仅驻留浏览器内存。
- 所有交互（筛选、搜索、打开详情）仅操作前端状态；刷新后恢复初始内容。
- 演示目录与现有产品前端、后端和运行目录分离。
- 不引入真实音频文件、密钥、用户名称、真实业务记录或网络请求。

## 主要组件

- `DemoDashboard`：整体布局、演示路径和视图切换。
- `ExecutiveSummary`：指标与今日重点。
- `MemoryCardGrid`：记忆筛选、搜索与卡片展示。
- `TaskBoard`：待办概览与详情入口。
- `PeopleInsights`：人物洞察与关联记录。
- `SourceTimeline`：模拟录音来源与跨录音关联。
- `DetailDrawer`：统一的详情侧边栏。
- `demoData`：静态的创始人工作记忆示例数据。

## 演示路径

1. 首页说明：一周录音已自动沉淀为可用的工作记忆。
2. 打开“今日重点”：展示系统如何给出决策、风险和下一步。
3. 进入一张客户反馈卡片，查看其来源、关联人物和后续任务。
4. 打开对应待办，说明责任与截止日期可追溯。
5. 进入跨录音关联，展示客户声音如何变成内部决策与执行闭环。

目标讲解时长为 2–3 分钟。

## 异常与验收

- 页面必须在无网络、无后端服务、无 API Key 的环境正常打开。
- 页面不应出现上传、真实转写进度、模型调用或真实数据读取行为。
- 所有详情入口可打开和关闭；筛选、搜索、日期切换可用。
- 刷新页面后数据恢复为预置虚拟数据。
- 演示入口须与现有应用入口区分，避免误操作真实产品。
