# 自主场景地图、本次概览与原生联网搜索设计

## 目标

在不预设场景类别的前提下，让每个上传批次获得完整、用户可见的「本次概览」，并以两次全量阅读分别完成高召回发现和高质量深度分析。模型可自主决定是否使用当前激活模型 API 的原生联网能力，最多五轮搜索；外部资料与录音证据保持严格区分。

现有 Compact 本地转写、已发布卡片、历史数据、隐藏画像和失败恢复能力必须保持可用。本功能在 `codex/autonomous-day-map` 分支实现，不改变当前已验收分支的行为。

## 产品结果

一个上传批次发布后，用户会看到：

1. 一张固定的「本次概览」，置于该批次内容最前。
2. 零到多张由模型自主命名、边界清楚的深度分析卡。

「本次概览」不是深度卡，也不占用深度卡数量。它记录本次材料中模型发现的独立场景、内容或事件；仅在材料支持时描述其发生、推进或内容，不强行给出建议。模型不得把环境中播放的媒体自动归因成用户稳定兴趣；可表述为“本次音频中出现/播放”，只有明确点播、评价、讨论或延展行为才可表述为用户主动关注。

## 自主场景地图

场景是模型发现的、在用户阅读时可独立理解的现实单元；它不受亲子、工作、内容消费或任何固定分类限制。每个场景必须包含：

- 自由命名的标题；
- 连续或可解释的源 segment ID 集合；
- 时间/文件范围；
- 简短的发生说明；
- 是否进入深度分析的建议与理由；
- 可选的外部核验需要。

模型应最大化发现覆盖率，但不把每句闲聊机械切成场景。两个单元在评价对象、理解方式或下一步显著不同，应拆分；同一个完整互动、讨论或事件应保持完整，不被拆碎。

## 编排

### 第一阶段：全量发现

本地转写完成后，将该上传批次的完整可靠转写交给当前激活模型。无论转写字符数，第一阶段都不使用现有信息笔记/检索回取作为默认输入。

模型返回结构化 `AutonomousDayMap`：

- `overview`：固定「本次概览」的标题、摘要和场景列表；
- `scenes`：自主场景地图；
- `search_action`：直接结束搜索，或给出第一轮原生搜索请求。

若当前模型的实际输入上限或服务端响应明确拒绝完整输入，任务进入现有超长笔记/原文回取链路作为降级方案；降级状态必须记录在版本状态中，并在本次概览元数据中可区分，但不向用户展示内部转写细节。

### 第二阶段：原生搜索循环

联网搜索由当前用户配置并激活的模型/API 提供的原生搜索工具执行，而不是使用额外 Key 或通用第三方搜索 Key。

- 最多五轮搜索；每轮最多五条查询。
- 每轮模型读取场景地图、此前搜索资料和剩余轮数；不重复发送完整转写。
- 模型自主决定是否搜索、换词、补充或交叉核验；服务端不对搜索价值做二次判断。
- 每轮的请求、模型决策、工具结果、错误和来源都持久化；恢复时不重复已完成轮次。
- 第五轮的工具结果返回后，模型必须收口到最终输出，不能要求第六轮。
- 搜索不可用、未开通、模型不支持、单轮超时或部分查询失败时，保留失败说明并继续分析，不阻断发布。

各 Provider Adapter 暴露统一的原生搜索能力探测与执行接口。Kimi 使用官方内置 Web Search 工具；DeepSeek、OpenAI 和后续提供商必须先以其已配置模型、当前 API 端点与 Key 进行能力探测。能力未知或探测失败时按“不支持”处理并降级为纯录音分析。

### 第三阶段：全量深度分析

模型再次读取完整可靠转写、第一阶段的自主场景地图，以及所有已保存的外部资料。它生成：

- 最终深度卡；
- 与每张卡关联的录音证据 ID；
- 与每张卡关联的外部来源 ID；
- 必要时的“未完成联网核验”说明。

第二阶段若未搜索或搜索失败，第二次全量阅读仍必须生成「本次概览」和深度卡。最终分析不得将外部资料改写成“录音里出现的事实”，也不得将外部资料作为录音证据 ID。

## 数据与呈现协议

新增的严格 Schema：

- `AutonomousDayMap`、`AutonomousScene`、`BatchOverview`；
- `NativeSearchDecision`、`NativeSearchQuery`、`SearchRound`、`SearchResultItem`；
- `ExternalSource`；
- 扩展 `AutonomousCard`，加入 `external_source_ids` 与可选核验状态。

`ExternalSource` 最少包含稳定 `source_id`、标题、URL、发布者（如可用）、发布时间（如可用）、摘录/支持说明和对应搜索轮次。最终卡引用的 source ID 必须映射到已持久化的真实工具结果；无效 ID 触发一次模型语义修复，仍无效则失败并保留旧版本。

发布时，一个批次创建一条独立的概览记录，并与深度卡共用批次与版本。历史 Feed 在同一批次中首先渲染「本次概览」，再渲染深度卡。旧批次没有概览记录时保持现有显示，不进行回填或删除。

卡片详情将“录音依据”和“外部资料”分开呈现：录音依据继续不展示原文墙或回听播放器；外部资料显示标题、发布者/时间（若有）、支持说明和可点击 URL。概览可显示“本次使用了 N 个外部来源”或“本次未完成联网核验”，但不暴露内部请求、密钥或搜索错误细节。

## 隐藏画像与安全边界

隐藏画像只接收最终卡片中可由录音证据支持的部分以及完整录音/必要回取原文。发送给画像提取器前必须剔除：

- 所有搜索原始结果；
- `ExternalSource`；
- 仅由外部资料支持的判断；
- 内部搜索轮次、错误和能力探测数据。

用户配置的模型 API Key 仍仅存在本地 Keychain；搜索与分析使用同一当前激活 Provider 的既有凭据。服务端只对工具调用数量、轮次和恢复状态做工程限制，不对模型的“是否值得搜”做价值判断。

## 状态、恢复与回滚

分析版本的 staged 状态增加：

```json
{
  "autonomous_day_map": {},
  "native_search": {"rounds": []},
  "autonomous": {}
}
```

恢复规则：

- 已完成场景地图不重复调用；
- 已完成搜索轮和工具结果不重复调用；
- 最终深度卡未完成时直接从第二次全量阅读继续；
- 版本发布前验证录音 evidence ID 与外部 source ID；
- 任何阶段失败都不得覆盖旧已发布批次或卡片。

若完整输入降级到现有超长路由，staged 状态同时保存降级原因与既有笔记/检索阶段，确保恢复不会丢失已完成工作。

## Prompt 要求

新增并版本化三类生产 Prompt：

1. `autonomous-day-map`：第一轮全量阅读。明确不得使用固定分类，要求完整发现与自由场景命名，生成「本次概览」。
2. `autonomous-native-search`：读取场景地图和历轮工具结果，自主决定继续搜索或结束；第五轮强制收口。
3. `autonomous-final-analysis`：第二轮全量阅读。基于完整录音、场景地图和外部资料生成深度卡，区分两类证据。

现有顾问式第二人称、三阶段卡片内容、引用真实性、卡片边界、媒体归属谨慎和隐藏画像规则继续适用。Prompt 不能列举亲子、播客、学习等封闭类别作为发现范围。

## 测试与验收

自动化测试至少覆盖：

- 首次全量阅读发现不在旧固定类别内的场景并生成概览；
- 一个批次恰好发布一张概览且排序在深度卡之前；
- 同一事件不拆碎、不同分析对象正确拆分；
- 无搜索时直接完成；一至五轮搜索后完成；第五轮强制收口；
- Kimi 原生搜索适配、能力探测失败降级、工具结果缓存与重启续跑；
- 非法 source ID、非法 segment ID、搜索失败、部分搜索失败；
- 外部资料不进入隐藏画像；旧批次无概览仍能读取；
- 完整输入被 Provider 拒绝时可降级到现有超长路径；
- 发布失败或新路径失败时不覆盖旧版本。

真实验收至少覆盖：

- 一次包含互动、媒体与多个非预设主题的批次，验证概览没有遗漏主要场景；
- 一次无需联网的个人复盘；
- 一次需要节目/产品/政策等外部核验的批次；
- 一次多轮搜索和一次中途重启；
- Kimi 与 DeepSeek 的真实能力探测与降级记录。

## 非目标

- 不引入独立搜索 API Key 或第三方通用搜索供应商；
- 不恢复六固定场景或 Event Map 导演作为前置门槛；
- 不把联网资料写入隐藏画像；
- 不删除、迁移或重跑现有已发布历史结果；
- 不在本功能中重新优化本地 Whisper 模型或 Compact 参数。
