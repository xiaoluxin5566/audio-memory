# Audio Memory 转写预计剩余时间设计

## 目标

在本地 Whisper 转写期间，为用户提供可信、可动态修正的预计剩余时间，降低长音频处理时的不确定感。预计时间是辅助信息，真实进度百分比仍是主要状态。

## 展示规则

- 转写开始但尚未完成首个新分块时，展示“正在估算剩余时间…”。
- 获得至少一个有效分块耗时样本后，展示“预计还需约 X 分钟”。
- 预计不足 60 秒时展示“预计不到 1 分钟”。
- 转写完成并进入模型分析后，不再展示转写预计时间，展示“正在生成分析结果…”。
- 中断状态不展示旧预计值；恢复后重新采样，先回到“正在估算剩余时间…”。
- 预计时间只显示整数分钟，不展示具体完成时刻。

## 估算算法

后端为每个运行中的转写任务维护仅限本次进程运行的分块计时样本：

1. 分块开始时记录单调时钟时间。
2. 分块成功完成并保存至少一个有效转写片段后，记录该分块的音频时长与处理耗时。
3. 取最近最多 3 个有效样本，计算加权实际速度：`音频毫秒数总和 / 处理秒数总和`。
4. 剩余音频时长为总时长减去数据库中已提交片段覆盖的时长。
5. `预计剩余秒数 = 剩余音频秒数 / 实际速度`。

不使用失败、取消、空输出或尚未提交的分块样本。预计值不持久化到 SQLite，程序重启或任务恢复后重新估算。

## 接口与前端

`GET /api/jobs/{job_id}` 和 `GET /api/jobs/active` 增加：

- `eta_state`: `estimating | ready | unavailable`
- `eta_seconds`: 非负整数或 `null`

前端仅根据接口字段格式化中文文案，不自行计算处理速度。轮询频率保持现有 1.2 秒，不新增额外请求。

## 边界与错误处理

- 总时长缺失、速度样本无效或任务不在转写阶段时，`eta_seconds = null`。
- 预计值不得为负数；异常大值按剩余音频总时长和最小有效速度保护。
- 单个分块速度突变只影响最近 3 个样本窗口，避免预计时间剧烈跳动。
- 恢复任务沿用已完成转写进度，但不沿用旧进程的速度样本。
- 进入分析、失败、中断、取消或完成状态时清除内存中的 ETA 样本。

## 验收标准

- 首个分块完成前页面显示“正在估算剩余时间…”。
- 一个有效分块完成后返回并展示预计剩余分钟数。
- 最近 3 个样本参与估算，第四个样本加入时淘汰最早样本。
- 中断恢复后 ETA 回到估算中，同时保留真实转写百分比。
- 转写进入分析后 ETA 文案消失并显示“正在生成分析结果…”。
- ETA 计算不改变分块转写、检查点恢复、历史发布或模型分析行为。
