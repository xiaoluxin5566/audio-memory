# 版本集成验收环境设计

## 目标

在多个功能合并到 `main` 后，用一条可执行命令启动当前目标版本的集成验收页面，不再依赖对话记忆或人工切换代码。

## 运行边界

- 正式版本仍为安装后的 beta.2，端口 `8765`，数据与进程均不受影响。
- 功能开发和集成验收共用本机开发端口：页面 `5173`，后端 `8766`；同一时刻只能有一个所有者。
- 集成验收只能从干净、与 `refs/heads/main` 完全一致的 main worktree 启动。启动时记录目标版本和确切 commit。
- 验收数据位于 main worktree 自己的 `.runtime/dev`，不读写正式数据，也不读写功能 worktree 的开发数据。

## 切换规则

1. 如果 `5173/8766` 未运行，直接启动集成验收。
2. 如果已是同一版本、同一 commit 的集成验收环境，幂等返回当前地址。
3. 如果是功能开发环境，先请求 `/api/jobs/active`。存在 `transcribing`、`analyzing` 等未结束任务时拒绝切换；没有活动任务时，验证所有者进程后安全停止，再启动集成验收。
4. 端口被未纳管进程占用、健康接口不可用、所有者记录无效时均拒绝自动停止。

## 命令和页面标识

- `./scripts/integration-start.sh v0.1.0-beta.3`
- `./scripts/integration-status.sh`
- `./scripts/integration-stop.sh`
- 页面顶部显示 `v0.1.0-beta.3 集成验收`，状态命令显示版本、commit、main worktree 和地址。

## 验收条件

- 活动任务时切换被拒绝，原运行时继续工作。
- 空闲功能环境可自动切换。
- 非 main、main 不干净或 main 已移动时拒绝启动。
- 停止命令只能停止已验证的集成验收所有者。
- 正式端口 `8765` 和正式数据路径不会被读写或停止。
