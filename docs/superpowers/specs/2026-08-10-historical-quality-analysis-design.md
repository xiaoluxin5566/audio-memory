# Local Fast V0.1 历史质量分析恢复设计

**状态：** 用户已批准实施  
**日期：** 2026-08-10  
**基线：** `codex/local-fast-v0-1@42a7abe`  
**范围：** 只重构 DeepSeek 分析，复用既有 3,442 个可靠句段，不执行 VAD、Whisper、风险门、说话人识别或 compact 转写

## 1. 背景与目标

当前最小 DeepSeek 修复已经证明请求、覆盖校验、六场景和原子发布均可完成，但真实长录音被压缩成一个低置信度 `casual_chat` 事件，最终合法发布 0 张卡片、0 条待办。对同一录音的历史分析仍能识别工作交流、招聘沟通、简历、下一轮沟通和产品方法等内容，因此本轮目标不是让数量机械地大于零，而是恢复历史链路的核心能力：局部切分、逐段识别、证据回读、分级归因和有价值的综合。

首轮使用同一 source job 和冻结句段创建新的 analysis version。旧失败版本和当前零结果版本都保留，不覆盖证据。

## 2. 方案比较

### 方案 A：只修改单次 event-map Prompt

调用数和实现量最小，但仍要求一次请求同时理解 3.5 小时、3,442 个句段并输出完整事件边界。当前“一整个下午都是闲聊”的结果已经证明单纯扩大上下文不能保证事件召回，因此不采用。

### 方案 B：确定性局部窗口 + 多次 event map + 服务端合并（采用）

先按文件、静音间隔和有界大小形成局部分析窗口，每个窗口独立调用 DeepSeek 还原事件，再由服务端验证并合并为一个全局事件地图。六场景仍各调用一次，但只接收已分配事件的紧凑证据投影。这个方案最接近历史链路的“先切簇、逐段回读、再综合”，同时不依赖人工硬编码时间窗。

### 方案 C：完整智能体循环

恢复联网检索、模糊片段二次转写和跨日报告记忆，最接近历史报告，但超出“阶段一只修 DeepSeek、复用现有句段”的边界。本轮只为后续保留接口，不实施。

## 3. 分析架构

```text
3,442 个可靠句段
  → 确定性局部窗口
  → 每个窗口独立生成局部事件地图
  → 局部证据与边界校验
  → 事件 ID 命名空间化并合并
  → 全局覆盖补全与身份聚合
  → 六场景基于紧凑事件证据串行分析
  → 历史质量闸门
  → 画像提取
  → 原子发布
```

### 3.1 局部窗口

新增纯函数窗口构建器。句段按文件和时间稳定排序，满足任一条件时切开：

- 文件发生变化；
- 相邻句段静音间隔不小于 45 秒；
- 当前窗口跨度将超过 20 分钟；
- 当前窗口将超过 400 个句段。

窗口不重叠，不复制句段。每个窗口至少包含一个句段，并记录 `window_id`、文件 ID、起止时间和句段 ID。上述四个参数进入 DeepSeek 参数指纹；本轮不临场修改。

20 分钟和 400 段是防止连续媒体或长谈话再次形成超大单次请求的硬上限；45 秒对应历史链路已经使用并产出有效场景簇的静音边界。

### 3.2 局部事件地图

每个窗口继续使用现有严格 `EventMap` Schema 和 DeepSeek V4 Flash 参数。局部请求只能引用本窗口的句段，服务端对每个窗口执行：

1. 未知证据 ID 拒绝；
2. 重复分配拒绝；
3. 未归类 ID 本地补全；
4. 事件起止时间必须覆盖其最早和最晚证据；
5. 事件 ID 改写为带窗口前缀的稳定全局 ID，父事件引用同步改写。

允许窗口没有可归类事件，但不得把未知 ID 或跨窗口证据带入全局地图。

### 3.3 合并与身份

全局事件地图按文件、起始时间和窗口顺序稳定合并，不用第二次模型调用猜测边界，也不自动合并相邻但语义不明的事件。局部多事件优先于一个巨型事件，避免再次损失召回。

`user_speaker` 仍遵守参数基准的 0.85 可靠阈值。只有同一个非空 speaker ID 在至少两个独立窗口中得到一致支持，且聚合置信度不低于 0.85，才提升为全局已确认身份；否则保持未知。事件自己的 `user_role` 和 `user_role_confidence` 可以保留“候选人、家长、佩戴者、参与者”等概率角色，但不得冒充声纹确认。

### 3.4 场景证据投影

六场景保持不增不减、串行执行。场景请求不再重复发送完整数据库字段，而是发送：

- 完整全局事件地图；
- 按事件分组的已分配句段：`id/start_ms/end_ms/speaker_id/text`；
- 画像快照。

正文不删减，未归类句段不进入场景生成，因为其证据无法通过事件归属校验。这样模型可以像历史智能体一样围绕局部事件回读，而不是再次扫描一份无边界的长文本。

### 3.5 工作沟通与分级归因

不新增第七场景。固定公共规则将 `meeting` 扩展为“有回顾价值的工作沟通”，包括招聘面谈、职业讨论、产品/业务深度交流、负责人沟通和非正式但高信息密度的工作讨论。普通寒暄仍不生成。

当全局身份未知时：

- 允许生成客观工作沟通卡、内容卡和不归因于用户的事实总结；
- 用“候选人、家长、参与者、录音中的一方”等角色描述，不写成“你”；
- 明确行动可以放入卡片内的 `meeting_todos`，owner 设为 `unknown` 并标记待确认；
- 禁止发布全局待办、用户成长评价、用户兴趣画像和强归因建议。

当全局身份可靠时，才允许现有全局待办、成长建议和画像规则生效。这样不会在“全部沉默”和“把别人当用户”之间二选一。

## 4. 历史质量闸门

发布前新增语义质量检查。满足任一条件时以 `analysis_quality_insufficient` 失败，不把空结果标记为成功：

- 可靠转写跨度不少于 2 小时，但全局事件不超过 1 个；
- 最长单一事件覆盖不少于 80% 的可靠转写跨度且边界置信度低于 0.70；
- 六场景全部 `should_generate=false`，但事件地图包含工作沟通、面试、媒体、亲子、承诺或深度讨论事件；
- 六场景全部为空且可靠正文不少于 10,000 字符。

质量错误保留可靠转写和局部分析结果，不发布半成品，并允许只重跑分析。

## 5. 历史对齐验收

自动化验收使用无隐私的合成句段，证明：

- 长录音会形成多个窗口和多个事件；
- 不同窗口复用的模型 event ID 不会冲突；
- 场景只能引用所属事件证据；
- 未确认身份仍可生成客观工作卡，但不能生成全局待办或用户画像；
- 长录音一事件或全空会触发质量错误。

真实 3,442 句段验收不把正文写入测试或日志，只记录聚合指标。页面至少应满足：

1. 事件地图不再是一个横跨约三小时的低置信度闲聊；
2. 能区分工作/职业讨论与招聘或电话沟通等独立事件；
3. 至少生成一张可回听证据的可见卡片；
4. 卡片能覆盖历史报告已经确认的工作、招聘、简历/下一轮沟通或产品方法中的至少两类；
5. 身份未确认时，把可能行动展示为“待确认行动”，不发布强归因全局待办；
6. 不虚构亲子、驾驶、正式会议决策或未出现的人名；
7. 0 卡片结果不得再次以 completed 发布。

旧链路的联网节目核验、模糊音频增强和跨日比较不在本轮，因此具体节目名称只有在转写明确出现时才允许展示。它们在阶段一页面验收后另行恢复。

## 6. 文件边界

预计新增或修改：

- `backend/src/audio_memory/analysis/windows.py`：纯窗口构建与局部地图合并；
- `backend/src/audio_memory/analysis/runner.py`：串行执行局部 event map、质量闸门和最终检查点；
- `backend/src/audio_memory/prompts/composer.py`：局部事件请求与紧凑场景证据投影；
- `backend/src/audio_memory/prompts/event-map.md`：强化局部边界和高召回规则；
- `backend/src/audio_memory/prompts/common-scene.md`：固定分级归因和工作沟通召回；
- `backend/src/audio_memory/prompts/event_schema.py`：把全局可靠身份阈值统一为 0.85；
- `backend/src/audio_memory/prompts/evidence.py`：保持强归因产物必须有可靠身份；
- `backend/src/audio_memory/analysis/errors.py`、重试 API：加入 `analysis_quality_insufficient`；
- 对应 unit/integration/E2E tests。

不修改本地转写、风险门、compact、卡片发布事务和前端信息架构。页面只复用现有卡片、待办、错误和证据回听能力。

## 7. 安全、费用与恢复

- 所有 DeepSeek 调用继续串行，沿用现有 timeout、max tokens、一次网络重试和一次 Schema 修复上限。
- 请求次数从固定 8 次变为 `局部窗口数 + 6 个场景 + 1 个画像`，重新分析前必须在安全指标中记录窗口数和预计逻辑调用数。
- 日志只记录窗口数、句段数、事件数、覆盖数量、调用耗时、token 和错误码，不记录转写正文、完整请求响应、原音频路径或 API Key。
- 任一局部窗口失败时不发布结果；已经完成的局部调用本轮不单独持久化，重新分析会重新执行 event map。最终全局事件地图仍使用现有原子检查点。
- 当前阶段不改变数据库 Schema，避免为一次恢复引入迁移风险。

## 8. 非目标

- 不降低身份可靠阈值换取全局待办数量；
- 不把建议伪装成用户承诺；
- 不硬编码真实录音时间窗、关键词或期望文案；
- 不把历史私人转写或报告正文放入仓库 fixture；
- 不在页面验收前开始 compact 本地转写实现；
- 不承诺逐字复现旧报告，验收的是事实召回、场景结构、证据和行动价值。
