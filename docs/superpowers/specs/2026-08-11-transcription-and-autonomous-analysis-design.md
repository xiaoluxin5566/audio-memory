# 本地转写与模型自主分析架构设计

日期：2026-08-11

## 1. 背景

当前产品把完整转写依次加工为 Event、场景导演选择、scene dossier 和六类场景结果。该流程提高了局部证据约束，但也在模型分析前过早切割上下文，并用固定 Schema 引导模型生成最低限度的结构化摘要。

真实数据验证暴露了两个直接问题：

- 同一次面试被拆成技术方案、项目经历和岗位介绍等多张卡片；
- 模型尝试合并跨 Event 内容时，又会因单 dossier 证据规则被拒绝。

目标架构只保留两个主要部分：本地高质量转写，以及模型自主分析。工程层不再决定语义边界，只负责可靠输入、最小输出协议、证据真实性和失败恢复。

## 2. 产品目标

系统应尽可能完整地保存音频信息，并让模型自主发现其中对用户最有价值的主题、联系、问题和建议。

成功结果应具备以下特征：

- 卡片按分析价值聚类，不按录音文件、时间窗口、Event 或固定场景拆分；
- 同一面试可以同时包含候选人经历、项目案例、岗位信息、薪资、能力评价和建议；
- 不同时间或不同录音中的内容可以在支持同一主题时进入同一张卡片；
- 详情可以包含事实、原句分析、不同观点、因果关系、模式、能力、风险、机会和建议；
- 内容结构由模型根据材料决定，而不是填满固定栏目；
- 所有原句和事实引用可定位到真实转写和原音频。

## 3. 总体架构

系统分为两个主要层次：

1. 本地转写层：将音频转换为尽可能准确、完整、可回听的连续文本。
2. 模型分析层：读取完整转写或长内容笔记，自主聚类并生成自由结构卡片。

数据流：

```text
音频
  -> 本地高质量转写
  -> 带时间戳和句段 ID 的连续文本
  -> 长度判断
       -> 短内容：完整原文直接分析
       -> 长内容：窗口信息笔记 -> 总编辑统一分析
  -> 模型自主聚类与深度分析
  -> 自由结构卡片
  -> 网页展示与原音频回听
```

## 4. 本地转写层

### 4.1 职责

本地层只输出事实材料：

- 尽可能完整的逐句转写；
- 文件 ID、录音时间、句段起止时间和稳定句段 ID；
- 转写可靠度以及无法确认的片段；
- 原始音频与句段播放范围的对应关系。

### 4.2 明确移除说话人区分

系统不再运行 diarization，不生成 `speaker_id`，不识别谁是用户，也不使用说话人身份作为后续分析前提。

模型可以根据文字中的问答关系使用“候选人”“招聘方”“其中一方”等语境角色，但这只是分析表达，不能成为系统确认的真实身份。无法确认归属时必须使用中性描述。

### 4.3 非职责

转写层不负责：

- 判断面试、会议、闲聊、亲子、内容消费等场景；
- 生成 Event 或语义边界；
- 决定卡片数量；
- 提取结论、画像、待办或建议；
- 将内容路由给多个场景模型。

### 4.4 验收指标

本地转写以以下指标验收：

- 信息保真度和漏句率；
- 数字、专有名词和关键事实准确度；
- 时间戳对齐精度；
- 处理速度和资源占用；
- 转写失败后的断点恢复能力。

## 5. 模型分析层

### 5.1 输入

分析模型只接收：

- 完整连续转写，或长内容的全部窗口信息笔记；
- 句段 ID 和时间戳；
- 用户可编辑的分析 Prompt；
- 最小输出协议；
- 需要回取时的原文查询能力。

不向模型提供 Event、dossier、固定场景标签或工程层预设主题。

### 5.2 模型职责

模型自主完成：

1. 阅读全部信息；
2. 判断哪些内容值得保留；
3. 发现主题并自主聚类；
4. 合并相同或高度相关的主题；
5. 决定生成零张、一张或多张卡片；
6. 自己命名卡片标题和摘要；
7. 自由组织详情章节；
8. 提取并分析关键原句；
9. 还原不同参与方的观点、回应和分歧；
10. 发现因果链、行为模式、能力、风险和机会；
11. 给出与具体录音证据相关的建议。

### 5.3 卡片边界

卡片代表一个具有独立用户价值的分析主题，而不是文件、时间窗口、对话段落或固定场景。

- 同一次面试默认是一张完整卡片，内部可以有多个自由章节；
- 同一次闲聊中的重叠问题必须合并；
- 同一段对话可以贡献给不同主题；
- 不同时间或不同录音可以共同支持同一张卡；
- 卡片数量完全由材料价值决定。

模型在输出前必须自行比较拟定卡片的核心问题、证据和用户价值，合并重复主题。工程层不实现语义去重器。

## 6. 短内容与长内容

### 6.1 短内容

当完整转写能够安全放入模型上下文时，直接使用单轮分析。不得为了流程统一先做摘要。

### 6.2 长内容第一阶段：信息笔记

超过上下文阈值时，按自然时间窗口处理。窗口模型只生成无损信息笔记，不生成最终卡片，不决定主题边界。

信息笔记保留：

- 发生的事情；
- 关键原句；
- 数字、事实、案例和条件；
- 观点、回应、反驳和转折；
- 可能值得跨窗口关联的线索；
- 对应句段 ID。

窗口应保留适量重叠上下文，避免在边界处截断完整表达。

### 6.3 长内容第二阶段：总编辑

总编辑读取全部窗口笔记后：

- 形成全局主题；
- 合并跨窗口和跨录音的相同主题；
- 判断哪些内容共同构成完整面试或完整问题；
- 决定最终卡片数量和结构；
- 针对高价值结论回取相关原文；
- 基于原文完成最终事实、原句分析和建议。

总编辑不能仅在摘要之上继续摘要。涉及关键结论、引语或建议时必须能够回到原始句段。

## 7. 最小输出协议

最终协议只约束传输和展示所需的最小字段：

```json
{
  "cards": [
    {
      "title": "模型生成的标题",
      "summary": "模型生成的摘要",
      "content": [
        {
          "type": "模型选择的内容类型",
          "title": "自然章节标题",
          "body": "完整分析内容",
          "items": []
        }
      ],
      "quotes": [],
      "recommendations": [],
      "evidence_segment_ids": []
    }
  ]
}
```

`content` 是有序自由章节。模型可以根据材料创建工作矛盾、危险循环、能力画像、话术优化、决策矩阵、风险、建议或其他章节。

`quotes`、`recommendations` 和证据引用是可选增强，不要求每张卡凑齐固定数量。系统不得因缺少某个预设栏目拒绝一张有价值的卡片。

## 8. 工程层校验

工程层只做：

- JSON 是否可解析；
- 最小字段类型是否合法；
- 引用的句段 ID 是否存在；
- 标注为原句的文字是否能在对应转写中找到；
- 音频播放范围是否有效；
- 是否包含明显不应写入日志或页面的内部字段。

工程层不再校验：

- Event 归属；
- dossier 授权；
- 固定场景类型；
- 单条分析是否跨局部边界；
- 卡片之间的语义重复；
- 模型是否填写固定分析栏目。

## 9. 页面设计原则

页面展示模型返回的有序自由章节，不固定为背景、结论、决策、问题和行动。

- 标题与摘要用于信息流浏览；
- 详情页完整展示自由章节；
- 原句分析使用独立视觉块，并支持回听；
- 建议使用独立视觉块，但保留模型给出的标题和组织方式；
- 长内容允许折叠，不截断保存；
- 页面不得把未知身份改写成“你”。

## 10. 失败处理

- JSON 语法错误：只允许一次格式修复，不重新解释内容；
- 引用不存在：只修复或删除引用，不重写整份分析；
- 单个长内容窗口失败：只重试该窗口；
- 总编辑失败：保存窗口笔记并重试总编辑，不重新转写；
- 分析失败：继续展示上一次成功版本；
- 没有高价值内容：允许返回空卡片；
- 原文过长：页面折叠展示，不在存储层截断。

## 11. 删除与保留范围

### 11.1 从主链路删除

- 说话人区分与用户说话人识别；
- Event Map；
- 场景导演；
- scene dossier；
- todo、meeting、parenting、content、growth、inspiration 六路独立生成；
- Event/dossier 证据完整性规则；
- 固定 Meeting 详情 Schema；
- 基于固定场景的卡片页面映射。

旧数据可保留只读兼容，但新分析链路不再依赖这些结构。

### 11.2 保留

- 本地音频导入、转写和断点恢复；
- 句段 ID、时间戳和音频回听；
- Provider 配置、Prompt 版本、历史重新分析；
- 失败不覆盖成功版本；
- 用户反馈和卡片追问；
- 隐私、安全会话和本地存储边界。

## 12. 测试与验收

### 12.1 转写测试

- 准确率、漏句率、时间戳和专有名词；
- 不运行 diarization；
- 长音频断点恢复；
- 速度和资源占用。

### 12.2 分析契约测试

- 自由章节可以解析和持久化；
- 不要求固定章节或固定数量；
- 引用句段真实存在；
- 原句可以在转写中定位；
- 长内容窗口与总编辑可独立重试；
- 失败不会覆盖上一次成功结果。

### 12.3 黄金样例

使用当前真实录音作为私有验收样例，不把原文提交到仓库。验收目标：

- 大致生成两张卡，而不是硬编码两张；
- 一张为完整面试分析，包含技术方案、AI 眼镜经历、岗位与薪资沟通；
- 一张为午间闲聊及工作、组织和职业思考分析；
- 能形成当前工作危险循环、产品能力画像、招聘话术优化和岗位筛选标准等跨片段洞察；
- 建议必须具体、有证据且能够指导下一步；
- 不捏造说话人身份、原句、数字或承诺。

## 13. 非目标

本阶段不做：

- 自动确认真实人物身份；
- 为卡片强制分类或打固定标签；
- 工程层语义聚类、去重或合并；
- 用规则判断面试边界；
- 自动把模型建议创建为待办；
- 把私有录音或转写加入公开测试数据。

## 14. 实施原则

- 先建立新链路，再移除旧主链路，保证可回滚；
- 优先跑通短内容单轮分析，再实现长内容总编辑；
- 以当前真实录音的最终价值作为验收标准，而不是仅以 Schema 通过率验收；
- 不在模型效果不足时继续增加固定业务结构；
- 所有主题边界、标题、内容组织和建议由 Prompt 与模型负责。
