# Beta 6 零配置托管存储热修设计

## 目标

修复全新安装后首次分析立即失败 `managed_storage_unavailable` 的发布阻断问题。用户不输入 OSS 配置或产品授权码，安装包不包含 OSS 长期 AccessKey 或全局共享的固定访问 Token。

## 设计

- 首次启动自动生成每安装实例独立的 Ed25519 密钥对；私钥以 `ThisDeviceOnly` 语义保存在当前运行环境的 macOS Keychain namespace，公钥可发送给 Broker。
- Broker 提供无感注册端点，为公钥签发受服务端密钥保护的安装凭据。凭据包含安装 ID、公钥、配额档位和版本，不包含 OSS 凭据。
- 每个 Broker 请求携带安装凭据、时间戳、随机 nonce、请求体 SHA-256 及私钥签名。Broker 验证凭据、签名、时钟窗口、nonce 重放、单设备配额和封禁状态后，才签发单对象短时效 URL。
- 注册端点必须有 IP/公钥指纹限流、全局每小时上限和可立即关闭注册的熔断开关；公开源码客户端无法证明“原版应用完整性”，这些滥用控制是 Beta 阶段的必要边界。
- nonce、每日用量、封禁和注册计数必须使用 Function Compute 所有实例共享的持久化原子存储。本期使用挂载持久卷上的 SQLite 事务帐本；未配置 `BROKER_SECURITY_DB` 时 Broker 拒绝启动，禁止回退为进程内状态。
- 对象继续使用随机 `temporary/` key，转写落库后立即删除，Bucket 24 小时生命周期兜底。

## 启动与失败语义

- 应用启动后在后台自动确保设备身份已建立；临时网络失败不得阻断页面启动，但托管存储 readiness 必须为不可用。后台以有上限的指数退避重试，用户再次上传或继续任务时可强制重试一次。
- 统一 readiness 增加 `managed_storage_ready`。未就绪时在读取上传字节前返回 `configuration_required`/`managed_storage`，不允许创建一个必然失败的任务。
- 已进入任务的存储授权、限流和服务不可用错误必须显示为“云端转写准备失败”，不得显示“模型分析失败”或“已保留完整转写”。
- 既有未完成 Beta 6 任务在完成自动设备注册后，从 ASR 阶段继续，不需要用户重新上传。

## 验收

1. 空的独立 Keychain 下启动，自动注册成功且可请求单对象上传 URL。
2. 安装包和静态资源不含 OSS AccessKey、Secret 或全局 Broker Token。
3. 签名篡改、过期时间戳、nonce 重放、超额和封禁均在 OSS 签名前被拒绝。
4. 不同设备不能读取或删除对方对象。
5. Broker 不可用时上传字节读取数为 0，UI 文案与真实阶段一致。
6. 使用全新数据根、空独立 Keychain 和开发端口完成 OSS→火山→报告的真实小样本验收，不读写正式环境。
