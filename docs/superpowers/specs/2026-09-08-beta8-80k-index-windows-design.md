# Beta 8 80k 索引分片与全日合并设计

## 目标

完整的 6,373 段逐字稿仍是报告的全量输入。80k 仅是事件索引阶段的单个主范围 token 上限。索引阶段将全量逐字稿分为三个连续主范围，每片携带约 1k token 的左右上下文。统一 V1 仍同时读取全量逐字稿和合并后的全日索引。

## 所有权

- 每个可靠片段只属于一个主范围，上下文只用于判断边界。
- 每个局部索引先对它收到的主范围和上下文做完整覆盖校验，再裁剪到主范围。
- 合并后重建 coverage，必须与全量可靠片段一一对应；缺失、重叠或未知 ID 直接失败。

## 跨片连续性

相邻两片共同观察分界前后的两个片段。如果两个局部索引都判定它们属于同一个活动，且活动类型、沟通目的和参与方式一致，则合并为一个全日主活动。如果两者都判定分界处已切换活动，则保留两个活动。两片结论不一致时停止合并，不用代码猜测。

被合并活动使用最左片的开始边界和最右片的结束边界，范围按原逐字稿顺序连接。局部 ID 全部改为确定性全局 ID，嵌入事件的父 ID 一并重写。

## 嵌入事件

嵌入事件的证据只保留当前主范围内的部分。完全位于上下文的事件丢弃；跨分界的事件可以在两片各保留一个有证据的导航项，不在确定性合并层主观合并不同话题。

## 失败与复用

已完成的中间 80k 索引可复用，因为本次修改只放宽统一 V1 卡片的证据 ID 上限，索引 Prompt 文本和请求未变。复用前必须校验它的逐字稿哈希、索引 Prompt 哈希、主范围边界和实际覆盖。任一不符就不复用。

之前只用中间切片运行的 V1 属于范围错误证据，不进入正式结果或任何后续检查点。
