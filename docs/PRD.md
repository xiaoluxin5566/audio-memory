# Audio Memory 产品需求文档（PRD）

| 项目 | 内容 |
|---|---|
| 产品名称 | Audio Memory / 音频 Always on Demo |
| 文档版本 | V1.0 |
| 更新日期 | 2026-08-05 |
| 当前阶段 | macOS 第一阶段用户体验版 |
| 文档状态 | 最新需求基线，待最终评审 |
| 适用平台 | macOS Apple Silicon |

## 一、需求背景

### 1.1 产品愿景

Audio Memory 通过用户主动上传的日常音频，挖掘一天中真正有价值的工作、生活和成长信息，帮助用户：

- 减少会议整理和待办记录成本；
- 改善家庭教育中的沟通与辅导方式；
- 整理每天消费的内容并获得更贴合自己的延伸推荐；
- 从真实工作和生活场景中获得可执行的成长建议；
- 保存容易消失但值得继续探索的闲聊灵感。

产品第一原则是“少但有用”。没有足够证据或实际价值时不生成内容，不以卡片数量作为体验目标。

### 1.2 目标用户

第一阶段面向愿意主动整理日常音频的体验用户，典型包括：

- 会议较多、需要持续整理决策与待办的知识工作者；
- 有儿童陪伴、辅导和家庭教育需求的家长；
- 经常消费播客、视频、发布会、音乐等内容，并希望形成持续兴趣脉络的用户；
- 希望基于真实行为而非通用问卷获得个人建议的用户；
- 需要频繁修改 Prompt、比较模型分析效果的产品与研发人员。

### 1.3 核心痛点

作为用户，当我一天中经历会议、家庭对话、内容消费和碎片交流时，我希望系统能从音频中自动找出真正重要的信息，这样我不用依赖记忆和手工整理，也能获得有依据、可执行的建议。

作为 Prompt 测试人员，当我修改分析 Prompt 时，我希望复用历史转写重新分析全部历史，而不是重新上传和等待 Whisper，这样我能快速验证 Prompt 效果。

### 1.4 需求成立判断

结论：需求成立，但第一阶段需要重点验证“用户愿意上传音频”和“模型结果是否持续有用”。

- 问题真实：会议遗漏、待办遗忘、家庭沟通复盘和内容消费碎片化均普遍存在。
- 使用频次：目标场景可按日发生，具备高频潜力。
- 核心门槛：第一阶段仍需用户主动导出和上传音频，门槛高于真正 Always-on 产品。
- 差异化：不只做转写或会议纪要，而是用统一事件地图覆盖工作、生活、内容与成长场景。
- 最大风险：模型若产生无依据、混淆事件或空泛建议，会快速损害信任。

## 二、产品目标与成功标准

### 2.1 第一阶段目标

1. 跑通“本地安装—配置模型—上传音频—本地转写—六场景分析—历史查看”的完整闭环。
2. 验证不同模型从同一份转写到最终建议的端到端效果。
3. 验证六场景产生的内容是否真实、有依据、对用户有帮助。
4. 建立可编辑、可版本化、可批量刷新历史的 Prompt 迭代框架。
5. 所有用户数据默认保存在本地，API Key 仅存入 macOS Keychain。

### 2.2 产品验证指标

第一阶段不默认上传行为埋点或音频内容，采用本地运行数据和用户访谈验证：

- 主链路完成率：有效格式、有效 Key 和网络正常时，上传任务能够完成转写并原子发布结果。
- 结果可信度：意见反馈中“完全准确”比例及“内容不准”的具体原因分布。
- 结果价值：用户是否保留、编辑或完成模型识别的待办，是否继续追问卡片内容。
- 场景命中质量：错误卡片、事件混淆、错误责任归属和虚构内容的数量。
- Prompt 迭代效率：修改 Prompt 后复用历史转写完成批量重分析，不再次运行 Whisper。
- 持续使用意愿：体验用户是否愿意在后续自然日继续上传音频。

具体量化基线由首轮体验数据建立，本 PRD 不虚构尚未存在的现状数字。

### 2.3 版本规划

#### 第一阶段：用户体验版

- macOS Apple Silicon；
- 只支持上传已有 MP3、AAC；
- 本地 Whisper 转写；
- Kimi、DeepSeek、OpenAI 三个分析厂商；
- 六场景卡片、全局待办、详情追问、意见反馈；
- 音频历史、Prompt 编辑和历史批量重分析；
- 隐藏用户画像，不向用户展示标签页面。

#### 后续：模型对比版

- 同一结构化转写同时交给多个模型分析；
- 并列展示模型结果、耗时、成本和用户反馈；
- 提供分析版本切换和差异对比；
- 页面结构与用户体验版分开设计。

## 三、产品范围与信息架构

### 3.1 安装和运行形态

- 用户通过终端安装并启动本地服务。
- 启动后自动打开本地网页。
- 不提供登录、注册、身份校验或多用户体系。
- 服务只监听本机 loopback；音频、转写、卡片、画像和反馈均保存在本机。
- 所有历史在程序关闭后长期保存，重新启动可继续查看。

### 3.2 一级导航

顶部导航在所有页面保持一致：

1. 信息流；
2. 音频历史；
3. Prompt 设置；
4. 重新分析全部历史；
5. 清除所有历史。

「重新分析全部历史」位于「清除所有历史」左侧。三个一级页面在同一浏览器标签内切换。

### 3.3 首页结构

- 左侧：模型与 API Key、音频上传、转写和分析进度。
- 右侧：全局待办和按自然日排列的卡片信息流。
- 默认空状态：右侧只显示“先上传音频”。
- 右侧不展示当前上传批次的处理中状态；只有完整结果发布后才进入信息流。

## 四、核心用户流程

### 4.1 首次使用

1. 用户通过终端完成安装并启动服务。
2. 页面自动打开，系统在后台读取 Keychain 并校验已配置厂商。
3. 首次使用时选择 Kimi、DeepSeek 或 OpenAI，明文输入 API Key。
4. 点击“保存并校验”。
5. 校验成功后保存至 Keychain、设为当前模型并关闭弹窗。
6. 校验失败时不覆盖旧 Key，弹窗保留输入并展示具体错误。

### 4.2 上传和分析

1. 用户拖拽或选择 MP3/AAC，可一次选择多个文件。
2. 文件按选择顺序逐个上传，每条独立显示进度。
3. 遇到不支持格式时暂停后续上传，移除错误文件后继续。
4. 用户点击“开始分析”，系统再次校验当前模型。
5. 系统锁定厂商、模型和 Prompt 快照。
6. 本地 Whisper 完成结构化转写和时间戳；本地说话人分段生成匿名 speaker 标识。
7. 当前模型先生成共享事件地图，再执行六场景分析。
8. 六场景全部成功并通过证据校验后原子发布。
9. 左侧上传区清空，右侧出现新结果，音频进入历史。

### 4.3 失败和恢复

- 转写中断：保存已完成分段，首页提示用户明确继续，不从头开始。
- 模型分析失败：保留完整转写，可使用当前厂商重试或切换厂商重新分析，不重复 Whisper。
- 页面关闭或服务异常退出：任务和检查点持久化，重新启动后恢复。
- 失败、取消或未完整发布的上传不进入音频历史和信息流。

### 4.4 修改 Prompt 和刷新历史

1. 用户在 Prompt 设置中编辑六个固定场景之一并保存。
2. 保存后，新上传默认使用新 Prompt，历史结果不自动变化。
3. 用户点击顶部“重新分析全部历史”。
4. 确认窗口展示上传批次数、文件数、文字量、当前模型、Prompt 版本、预计调用范围和费用提醒。
5. 用户确认后，系统复用结构化转写，从最新上传向最早上传逐批重分析。
6. 每个原始上传批次完整成功后切换到新分析版本；失败时保留旧版本。
7. 用户可停止任务；服务重启后可以继续。

## 五、详细功能需求

### 5.1 模型与 API Key

#### 支持范围

- 固定支持 Kimi、DeepSeek、OpenAI；不允许用户新增或删除厂商。
- 每个厂商独立保存 Key。
- 第一阶段不提供具体模型版本选择，使用系统内置默认模型。
- 新厂商配置成功后自动成为当前模型。
- 已配置厂商可重新校验、修改 Key 或设为当前模型。

#### 存储与展示

- API Key 只保存在 macOS Keychain。
- 输入时使用明文展示，关闭配置弹窗后不回显完整或脱敏 Key。
- SQLite、日志、反馈、Prompt 和接口响应均不得保存或返回 Key。
- Keychain 不可访问时显示独立状态，不误报为未配置。

#### 校验

- 启动程序、保存新 Key、重新校验和开始分析前触发真实模型请求。
- 校验成功必须满足 HTTP 和厂商业务状态正常、响应可解析、模型正文规范化后严格等于 `OK`。
- 限流显示倒计时；认证失败、余额不足、权限不足、网络错误和超时使用不同文案。
- 候选新 Key 校验失败不覆盖正式 Key。

### 5.2 音频上传

- 第一阶段只支持 MP3、AAC，扩展名和实际内容都要校验。
- 支持点击选择和拖拽，多文件按选择顺序分批上传。
- 每个文件展示名称、格式、大小、上传进度和错误状态。
- 遇到不支持格式时停止加载后续文件，提示“不支持该文件格式，请上传 MP3 / AAC 格式文件”。
- 全部上传完成后才允许开始分析。
- 开始分析前上传队列不绑定模型，切换厂商不清空文件。
- 完成分析后自动清空上传区，不提供“查看本次结果”按钮。

### 5.3 本地转写和进度

- 三个模型厂商统一使用本地 MLX Whisper Large V3 Turbo 转写，原始音频不发送给模型厂商。
- 转写保存可恢复片段、词级时间戳和匿名说话人标识。
- 真实进度基于已提交转写片段，不使用虚假匀速动画。
- 首个有效耗时样本产生前显示“正在估算剩余时间…”。
- 有稳定样本后显示“预计还需约 X 分钟”；不足一分钟显示“预计不到 1 分钟”。
- 中断恢复后重新估算速度，但保留已完成百分比。
- 进入模型分析后隐藏转写 ETA，显示“正在生成分析结果…”。

### 5.4 事件地图和分析原则

- 事件描述“发生了什么”，场景描述“从哪个角度分析”，两者为多对多关系。
- 同一场会议可以同时产生会议纪要、待办和成长建议。
- 每个事实、推断和评价必须绑定真实 `event_id` 和证据片段。
- 禁止跨事件拼接原因、参与者、结论或因果关系。
- 禁止把媒体内容中的行动号召识别为用户待办。
- 第一阶段不要求用户确认哪个声音是自己；模型推断置信度低于 0.70 时，不生成责任归属、个人评价或画像更新。
- 没有足够证据或价值时不生成对应场景。

### 5.5 信息流与排序

- 全局待办始终位于时间线之上。
- 时间线按自然日分割，最近上传批次在上方。
- 同一个上传批次的默认顺序：会议纪要、家庭教育、内容推荐、成长建议、闲聊灵感。
- 没有命中的场景不显示空卡片。
- 重分析不改变原上传时间、自然日和信息流位置。
- 右侧不使用推荐排序算法。

### 5.6 全局待办

#### 生成规则

- 只识别用户明确承诺、接受或确定执行的行动。
- 愿望、灵感、假设、他人任务、已经完成的事项和媒体行动号召不是待办。
- 多次出现的同一待办保守去重，无法确定时保持独立。

#### 用户操作

- 支持编辑、完成和删除，不支持回听。
- 未完成待办优先展示，已完成待办进入弱化区域。
- 已过期的待办由系统自动完成，并记录完成来源。
- 历史重分析保留用户编辑、完成和删除状态；删除过的待办不得复活。

### 5.7 会议纪要卡片

#### 外部卡片

- 标签：会议纪要；
- 会议主题：AI 生成；
- 核心结论：AI 生成；
- 右上角：会议开始和结束时间；
- 底部小字：明确决策数量、会议待办数量；
- 不展示会议时长、表达问题或优化建议。

每个独立会议生成一张卡；普通零散工作交流缺乏明确议题、决策、待办、方案讨论或跨角色协调时不生成。

#### 详情页

- 会议概览与参与者；
- 核心结论；
- 讨论主题；
- 明确决策；
- 未决问题；
- 会议待办；
- 完整转写引用与时间边界由底层保存，第一阶段不直接展示证据 ID。

追问默认只围绕当前会议回答。

### 5.8 家庭教育卡片

#### 外部卡片

- 标签：家庭教育；
- 主标题：AI 生成；
- 核心结论：AI 生成；
- 单个互动显示时间；多个互动显示“多个互动片段”。

同一次上传中的多个亲子互动汇总为一张卡，但详情必须按事件分组，不混合困难、原因和建议。

#### 详情页

1. 背景信息：复现真实互动场景；
2. 找出问题所在：识别孩子困难、情绪信号和可能问题；
3. 给出切实建议：结合本次证据和隐藏画像给出方法、步骤与自然口语化建议话术。

不得仅凭一次正常互动给孩子或家长贴标签，不进行医学或心理诊断。

### 5.9 内容推荐卡片

#### 外部卡片

- 标签：内容推荐；
- 标题：AI 生成；
- 核心内容：AI 生成。

同一次上传汇总为一张卡，不同视频、播客、发布会、歌曲等必须在详情中按事件分开。

#### 详情页

1. 这次你都听了：逐项列出内容展示标题和简介；
2. 更贴合你的内容：优先推荐高度确认真实存在的作品，否则提供可搜索主题。

只有音频明确说出作品名称时才展示来源标题；模型推测名称不得伪装成事实。单纯背景播放或“随便看看”不形成长期兴趣。

模型仍需在底层生成有证据支持的兴趣信号，用于隐藏画像和后续推荐；第一阶段不在内容卡或其他页面展示“个人标签更新”。

### 5.10 成长建议卡片

#### 外部卡片

- 标签：成长建议；
- 标题：AI 生成；
- 核心内容：AI 生成；
- 显示“仅基于本次上传的 N 个音频文件”。

成长建议不是自然日汇总，只分析本次上传音频；同一次上传汇总为一张卡，按成长方向分组。

#### 详情页

1. 场景：还原用户遇到问题的具体环境；
2. 问题：引用可观察行为、外界反馈和结果；
3. 建议：给出可执行目标、方法、最多三个步骤、示范话术、小练习和成功信号；
4. 值得保留：存在正向证据时指出有效行为。

重复模式至少需要两个独立事件。单一高影响事件只有在用户身份可靠、行为证据置信度不低于 0.80，且存在明确负面反馈或失败结果时才可生成问题型建议。

### 5.11 闲聊灵感卡片

#### 外部卡片

- 标签：闲聊灵感；
- 主标题：AI 生成；
- 内容：AI 生成。

同一次上传中的高价值灵感融合成一张卡，详情按事件分组。

#### 详情页

1. 发生时背景；
2. 对话梗概：忠实整理，不做过度扩写；
3. 对话价值：说明为什么值得用户保留；
4. 建议推荐：给出下一步探索方向。

是否生成由模型综合判断，不能依赖“不错”“有价值”等关键词。普通赞美、复述外部观点、已明确形成的待办或没有继续探索价值的内容不生成灵感卡。

### 5.12 卡片详情、追问和意见反馈

- 点击任意卡片后，在右侧信息流区域打开覆盖式详情页。
- 关闭后回到原信息流和滚动位置。
- 详情顶部只有一个“意见反馈”入口。
- 点击后弹窗展示“完全准确”和“内容不准”。
- “完全准确”可直接提交；“内容不准”时才展示必填输入框和提交按钮。
- 继续追问位于详情内容最底部。
- 用户消息右对齐，AI 消息左对齐，均使用气泡。
- QA 直接展示在详情内容下方并用分割线区分。
- 追问只使用当前卡片、当前上传批次转写、相关隐藏画像和该卡历史 QA。

每次反馈在本地“意见反馈”文件夹生成独立记录，至少包含：

- 场景类型；
- 音频文件信息；
- 完整转写原文；
- 当时的生成内容；
- 模型厂商、模型和 Prompt 快照；
- 反馈选项与用户文字；
- 若存在追问，包含完整 QA。

### 5.13 音频历史

- 只展示完整分析成功并发布的音频。
- 按自然日分割，越近越靠前。
- 同一次上传中的文件作为同一历史上传批次展示。
- 第一阶段不支持编辑、删除、搜索、回听或单条重分析。
- 页面不展示分析中或失败状态；未完成任务视为没有进入历史。

### 5.14 Prompt 设置

- 固定六个场景：待办、会议、家庭教育、内容推荐、成长建议、闲聊灵感。
- 用户只编辑完整自然语言 Prompt，页面只提供“编辑”和“保存”。
- 不支持新增、删除、排序、停用、恢复默认、页面测试或版本对比。
- 系统基础 Prompt、公共分析规则、事件地图 Prompt 和 JSON Schema 固定且不可编辑。
- 用户 Prompt 与固定安全规则冲突时，以固定规则为准。
- 保存后写入本地 `current.md`，旧版本归档；新分析使用新版本。
- 用户自己改过的 Prompt 在程序升级时不得被默认 Prompt 覆盖。

### 5.15 重新分析全部历史

#### 入口与范围

- 顶部常驻入口，位于“清除所有历史”左侧。
- 没有已完成历史时禁用。
- 处理单位是原始上传批次，不是单个音频文件。
- 同一时刻只允许一个历史重分析批次。

#### 执行规则

- 复用原始音频记录、结构化转写、时间戳和说话人结果。
- 固定当前厂商、模型、凭据代次、完整 Prompt 内容及哈希、固定规则版本和批次开始时的画像快照。
- 事件地图满足版本与证据完整性条件时复用，否则只重建事件地图。
- 每个原始上传批次六场景全部成功后切换到新分析版本。
- 失败项继续展示旧版本，其他历史项继续。
- 不改变原上传日期和信息流顺序。
- 新 Prompt 不再命中的旧场景从当前信息流消失，但旧版本、QA 和反馈仍保留。

#### 调度和停止

- Whisper 可以与历史任务并行；同一时刻只执行一个远程模型任务。
- 新上传的模型分析优先，历史任务在当前项结束后让路。
- 支持“停止重新分析”，当前项结束后不再领取新任务。
- 页面刷新、关闭或服务重启后状态可恢复。
- 历史重分析运行或暂停时禁用“清除所有历史”。

#### 版本与用户数据保护

- 原始音频和转写只有一份，分析版本不得复制。
- 旧卡片和 QA 不物理删除；信息流只展示当前版本。
- 新版本卡片的追问区为空，不混入旧版本 QA。
- 用户编辑、完成和删除过的待办状态保留，删除墓碑防止待办复活。
- 全部历史项使用同一画像快照分析，结束后基于所有当前版本统一重建隐藏画像。

### 5.16 清除所有历史

- 顶部常驻入口，点击后显示二次确认，不要求输入确认文字。
- 删除全部音频、转写、分析版本、卡片、QA、待办、删除墓碑和隐藏画像。
- 保留 API Key、模型配置、Prompt 配置与已经导出的意见反馈文件。
- 历史重分析或其他远程模型任务运行/暂停时不允许清除。
- 清除成功后回到信息流空状态“先上传音频”。

## 六、状态与异常处理

| 模块 | 状态/异常 | 产品处理 |
|---|---|---|
| 模型 | 初始化、未配置、校验中、可用、不可用、Keychain 不可访问 | 分状态展示；不可用时仍允许进入配置、历史和 Prompt |
| 模型限流 | 返回 Retry-After 或冷却时间 | 显示倒计时，冷却期禁用重复校验和分析 |
| 上传 | 不支持格式 | 暂停后续文件，移除问题文件后继续 |
| 转写 | 0% 或尚无有效样本 | 展示真实进度和“正在估算剩余时间…” |
| 转写中断 | 服务或系统退出 | 保存检查点，重新启动后提示继续 |
| 模型分析 | 网络、余额、认证、Schema 错误 | 保留转写；按错误类型重试、修改配置或切换厂商 |
| 场景结果 | 某场景失败 | 普通上传不发布半成品；历史重分析保留该批次旧版本 |
| Prompt 保存 | 版本冲突或写入失败 | 不覆盖当前可用版本，保留用户编辑内容 |
| 历史重分析 | 停止、部分失败、凭据改变 | 保存成功项；失败项保留旧结果；凭据变化需重新确认 |
| 画像重建 | 内容成功、画像失败 | 新内容继续生效，旧画像保留，允许单独重试画像 |
| 清除历史 | 有运行或暂停任务 | 禁用清除并说明原因 |

## 七、数据、隐私与初始化

### 7.1 本地数据

默认目录：

```text
~/Library/Application Support/AudioMemory/
├── audio-memory.sqlite3
├── audio/
├── staging/
├── prompts/
├── models/
└── 意见反馈/
```

- 原始音频不发送给 Kimi、DeepSeek 或 OpenAI。
- 只有转写文本、结构化事件信息和必要隐藏画像发送给当前分析厂商。
- API Key 只存在于 Keychain 和单次请求内存。
- 清理文件前必须校验路径位于应用目录，禁止删除用户目录中的其他文件。

### 7.2 隐藏用户画像

- 从用户第一次上传音频开始建立。
- 包含有证据支持的基础属性、兴趣偏好、近期关注、目标和稳定行为信号。
- 第一阶段不给用户提供独立标签查看页面。
- 画像只用于内容推荐、成长建议和个性化表达，不得覆盖音频事实。
- 用户身份置信度不足时不更新画像。
- 清除历史时删除画像。

### 7.3 初始化与历史迁移

- 首次安装创建本地目录、SQLite、默认 Prompt 和模型文件。
- 重复安装不得破坏 Keychain、用户 Prompt 和本地历史。
- 数据库升级使用可回滚迁移，不重写原始音频与转写。
- 新分析版本结构上线时，为现有每个已完成批次建立初始版本并设为当前版本。
- 已有 QA、反馈索引和待办迁移到对应初始版本。
- 无法可靠生成待办来源指纹的旧待办标记为用户保护状态，历史重分析不得覆盖。

### 7.4 本地 Web 安全

- 服务只监听 loopback。
- 严格校验 Host 和 Origin，拒绝跨站请求。
- 会产生费用或修改数据的接口要求随机本地会话令牌和幂等键。
- 不允许其他网页静默触发历史分析或清除操作。

## 八、非功能需求

### 8.1 可靠性

- 单个上传批次原子发布，不展示半成品。
- 每个模型场景保存检查点，异常退出后尽量避免重复调用。
- 极端情况下模型返回后、检查点写入前崩溃，可能重复一次外部请求；产品不承诺厂商绝对幂等。
- 音频、转写和当前发布结果必须在服务重启后保持完整。

### 8.2 性能

- 转写不得阻塞页面浏览历史、详情或 Prompt。
- 长音频采用分块转写；说话人识别采用有界窗口，避免一次性加载全部 PCM。
- 历史重分析不执行 Whisper，耗时仅由本地读取、事件地图必要重建和模型请求决定。
- 第一阶段远程模型任务串行执行，优先保证稳定性和费用可控。

### 8.3 兼容性

- 第一阶段仅支持 macOS Apple Silicon。
- 浏览器页面适配常见桌面窗口尺寸，不支持移动端。
- 音频仅支持 MP3/AAC。

### 8.4 可诊断性

- 正式日志只记录归一化错误代码。
- 厂商原始错误仅进入有限容量的纯内存诊断缓冲区，并先移除认证信息。
- `doctor.sh` 只检查环境和状态，不修改用户数据或输出 Key。

## 九、埋点与用户研究

第一阶段默认不向外部服务器上报行为或内容。允许在本地记录不含音频正文和 Key 的运行指标，用于用户主动导出或现场测试：

- 模型配置成功/失败类别；
- 上传批次数、文件数、音频总时长；
- 转写耗时、模型分析耗时和失败阶段；
- 每场景 `should_generate` 结果；
- 卡片打开、追问、反馈、待办编辑/完成/删除；
- Prompt 保存版本与历史重分析完成/失败数量。

任何外部遥测、崩溃上报或数据上传必须在后续版本单独设计并获得用户明确同意。

## 十、第一阶段非目标

- 不做实时 Always-on 录音；
- 不支持 Windows、Intel Mac、iOS、Android；
- 不上传原始音频给模型厂商；
- 不让 DeepSeek、Kimi 或 OpenAI 直接完成音频转写；
- 不提供用户账号、云同步或多人共享；
- 不提供音频播放、回听、编辑或单条删除；
- 不提供独立可见的个人标签页面；
- 不允许新增、删除或停用场景 Prompt；
- 不提供前端分析版本切换与差异对比；
- 不并行运行多个历史重分析批次；
- 不在保存 Prompt 后自动刷新历史；
- 不提供推荐排序算法；
- 不进行医学、心理、法律或财务诊断。

## 十一、发布验收标准

### 11.1 安装与启动

- 安装脚本可重复执行，不破坏模型、Prompt、Keychain 和历史。
- 启动后只有一个本地服务实例并自动打开首页。
- 首页、音频历史、Prompt 设置和健康检查可访问。

### 11.2 主链路

- 三厂商均可独立配置和真实校验。
- MP3/AAC 多文件上传、暂停、移除错误文件和独立进度正常。
- 三厂商都复用同一本地 Whisper 转写。
- 中断恢复不丢失已提交转写。
- 六场景全部成功后才发布，失败时不进入历史。

### 11.3 结果体验

- 待办全局置顶，编辑、完成、删除和过期自动完成正常。
- 卡片按自然日和固定场景顺序展示。
- 会议、家庭教育、内容推荐、成长建议和闲聊灵感均满足各自外部字段与详情结构。
- 多事件在同一汇总卡中按事件分组，不发生跨事件混淆。
- 详情页、QA 气泡、意见反馈弹窗和完整记录正常。

### 11.4 Prompt 与历史重分析

- 六场景 Prompt 只支持编辑和保存，用户修改内容不会被升级覆盖。
- 修改 Prompt 后可复用所有历史结构化转写重新分析，Whisper 调用次数为零。
- 同一次上传的多个文件只生成一个新分析版本。
- 单条历史分析失败保留旧版本；成功后原子切换。
- QA、反馈和用户待办状态可完整溯源且不会被重置。
- 停止、凭据变化、页面刷新和服务重启均按设计恢复。
- 历史重分析不改变原日期和信息流排序。

### 11.5 隐私与安全

- Key 只在 Keychain 中存在。
- SQLite、Prompt、反馈、日志和 API 响应无 Key。
- 原始音频不离开本机。
- 非同源网页不能调用有费用或破坏性的本地接口。
- 清除历史准确删除本地历史并保留 Key、Prompt 和反馈文件。

## 十二、待后续产品决策

以下不阻塞第一阶段开发，但需要依据体验数据决定：

1. 用户是否需要显式确认自己的说话人身份。
2. 卡片数量增长后是否增加分类标签或筛选。
3. 是否开放分析版本清理，控制长期磁盘增长。
4. 模型对比版的并列布局、评分方式和结果保留策略。
5. 从“上传已有音频”升级到真正 Always-on 录音的隐私、功耗和权限方案。

## 十三、技术方案入口

本 PRD 的研发实施拆分至少包括：

1. 本地安装、运行与存储；
2. Keychain 与三厂商适配器；
3. 上传、Whisper、说话人识别与检查点；
4. 事件地图、六场景 Prompt 与 Schema；
5. 卡片、待办、QA、反馈与隐藏画像；
6. 分析版本、历史批量重分析与统一任务调度；
7. 前端三页面和全部状态；
8. 自动化测试、真实模型评测和安装验收。

具体技术实现以对应设计规格和实施计划为准；若与本 PRD 发生冲突，以本文档中标记的最新产品决策为准，并同步修订下游文档。
