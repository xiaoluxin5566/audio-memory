# 云端 ASR 评测方法归档

归档日期：2026-08-19  
来源分支：`codex/cloud-asr-evaluation`  
来源顶端：`2ee16d9`

## 结论

该分支保留了一套可复用的云端 ASR 事实评测方法和经过测试的评测工具，但没有形成可用于产品选型的真实供应商结果。没有经用户再次授权上传真实音频，也没有读取真实凭据或执行付费 API 调用。因此不能据此宣称火山或阿里云在准确率、速度、成本或稳定性上胜出。

Audio Memory beta.3 仍以本地转写为唯一默认路径。云端 ASR 运行时代码不迁入 beta.3，以免扩大网络、凭据、隐私和维护边界。

## 值得保留的方法

1. 同一源音频必须以 SHA-256、精确时长、字节数、编码、声道和采样率固定身份；任何输入不一致都拒绝并列比较。
2. 所有供应商使用相同切片与相同重叠区。局部时间戳统一映射回源时间轴，无法确认的边界重复保留并标记冲突，不能静默删除。
3. 两次运行采用交叉顺序，完整保留慢运行、失败、重试、请求 ID、分阶段耗时和结果波动，不用成功重跑覆盖失败事实。
4. 关键字段核验采用盲评：人名、组织、项目、金额、日期、承诺、责任人和截止时间均需回听音频证据；模型只能生成候选清单，不能充当正确答案。
5. 最终报告必须使用同一分析供应商、模型 ID、Prompt 快照和结构化合同，并分别报告 ASR 错误、报告事实错误、无证据结论和来源误归因。
6. 只输出并列事实，不计算综合总分或自动排名；无法建立全量人工金标时，不声称严格召回率。

## 安全与证据边界

- 真实上传、对象存储、付费 API 和 Keychain/环境凭据读取必须重新获得用户授权。
- API Key、签名 URL 查询参数、音频、转写正文、本地路径和原始厂商响应不得进入 Git、普通日志或脱敏报告。
- 私密运行目录应为 `0700`，私密文件为 `0600`；异常消息只允许稳定错误码，不回显响应正文或秘密值。
- 任何切片失败、空结果、时间戳倒退、明显越界或时长不一致，都必须阻止“完整成功”报告。

## 如需恢复实验

原实现可从提交 `2ee16d9` 恢复。重新开展时，应从当时最新 `main` 创建新的独立实验分支，只选择性迁移统一类型、切分合并、证据合同和对应测试；不要整体合并旧分支，也不要把实验 runner 或另一家供应商代码带入生产包。
