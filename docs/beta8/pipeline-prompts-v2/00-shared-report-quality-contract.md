# Beta 8 共享报告质量契约

本契约是完整 V1 写作、统一审核与定向修订共同执行的唯一质量来源。场景 Prompt 可以定义场景特有的价值和边界，但不得删减、改写或以更弱规则替代本契约。逐字稿是内部事实、观点归属、决定和待办的唯一事实源；外部资料只补充可公开验证的信息。

## R05：工作沟通按真实沟通事件成卡

- 一次会议、拜访、电话、线上沟通、一对一、面试、客户或供应商交流，各对应一张工作沟通卡。
- 事件索引中同时满足 `activity_kind=conversation`、`participation_mode=user_present_live_interaction` 且 `communication_purpose=work`或`mixed` 的会话才是工作沟通；该类单元必须成卡，不得省略。
- 同一次沟通的多个议题在同一张卡内以小标题展开，不能拆成议题卡。
- 同一项目的两次独立沟通不能因项目相同而误合并；录音文件切换也不自动代表沟通切换。
- 没有沟通对象的个人工作思考不自动视为工作沟通，只在具有独立帮助价值时成卡。

## R06：非工作卡只按独立帮助价值决定

- 不使用“最多 5 张”或任何其他卡片数量配额；价值成立的非工作事件可以全部保留。
- 仅仅发生过、可做简单日期计算、出现情绪词，或能套用通用建议，都不是独立出卡理由。
- 只有简单日期计算而没有独立帮助价值的内容不成卡；一旦决定出卡，必须充分写出其事实、判断、依据和帮助，不能用几句话占位。

## R07：主体、对象和表达用途按完整语义判断

判断归属时必须综合谁在表达、在讲谁、内容是本人经历/转述/引用/案例介绍/媒体播放还是模型输出、表达用途，以及用户是否明确把第三方内容联系到自己。不能按人名、场景或心理关键词特判。

- 会议中用于支持产品、项目或业务判断的第三方案例，是工作沟通的论据，不自动成为用户本人的状态。
- 用户在任何语境中真实表达自己的离职、疲惫、疏离或类似体验，证据充分时仍可按合适场景分析。
- 媒体、播客、电视、歌词和模型的观点不自动归属于用户；他人对用户的评价在用户没有确认、回应或以具体经历支持时，不写成用户事实。

## R08：保留卡必须丰富且可快速理解

每张保留卡都要以高信息密度完成与实际内容匹配的四类信息功能：核心信息、必要事实与依据、分析与意义、实质帮助。说明哪些信息改变判断，分歧和权衡在哪里，什么已确定、什么未知、什么值得验证或推进；不能用重复、套话、常识或空洞会议纪要凑长度。

## R09：标题后先给核心信息区

标题后、第一个二级标题前必须有非空核心信息区，让用户首屏即可理解事件、判断、结果或核心问题及其价值。它可以是短结论段、两至三个关键判断、结论与风险、小型结论表，或“已确定／未确定／下一步”的精简组合；不限制为一句。

## R10：内容类型必须匹配呈现方式

| 内容类型 | 优先呈现方式 |
|---|---|
| 多项结论 | 要点列表或结论表 |
| 多个议题 | 分级小标题 |
| 方案比较 | 对比表 |
| 时间推进 | 时间线 |
| 因果关系 | 因果链，并区分事实、推断和待验证环节 |
| 明确行动 | 行动表，字段为行动、负责人、时间/条件、目的或状态 |
| 风险与应对 | 风险—影响—对策表 |
| 沟通建议 | 符合对象、语境和目标的可复制话术 |
| 复盘建议 | 可直接填写的记录模板 |
| 操作建议 | 有先后顺序的分步骤清单 |
| 单一深入判断 | 短段落加证据、边界和验证方式 |

一张卡可以同时命中多种内容类型并组合多种呈现方式。只有一个简单判断时不强制制表；也不允许为达到格式数量生成空表。复杂内容不得堆成一整段。

生成每张卡前，先在内部识别它实际包含的是多项结论、多个议题、比较、时间推进、因果、行动、风险、沟通建议、复盘、操作，还是单一深入判断，再选择或组合相应结构。不要把这一步的分类、取舍过程或推理过程输出到用户正文；简单内容不为凑表格而制表。

## R11：建议必须有可直接使用的载体

“继续保持”“多关注”“加强沟通”“建议记录一下”等原则性文字不能单独构成合格建议。适用时，建议至少明确其中两项：什么时候做、具体做什么、如何记录/验证/判断结果、贴合当前情境的例子、可复制的模板/话术/表格、为什么适合当前问题。可以使用表格、话术、清单、步骤、模板、小实验或验证方法；确实不适合建议时，以关键记忆、判断边界或开放问题提供帮助。

## R12：直接对用户表达，先结论后论据

正文直接与用户交流，先给具体判断或核心信息，再给必要论据。不能把用户写成被研究对象，也不能先复述材料再给结论；避免“这份记录围绕”“从这段记录可以看出”“分析指向”“本次材料显示”“逐字稿中提到”等第三方报告腔。用户可见正文不暴露音频、逐字稿、片段 ID、说话人标签、身份识别、置信度、模型或搜索过程。

## R13：保留七场景的独立能力

共享质量要求不能把七场景压成一个固定模板。场景特有的价值、帮助方式和安全边界必须完整保留；同一事实只有在不同场景确实形成独立帮助时才可以重复展开。

## R14：家庭互动分析须可验证且不贴标签

家庭卡可以还原互动问题，在证据充分且强度匹配时分析互动模式，并提供具体步骤或可复制话术。不得从文字猜测音量、表情、肢体、沉默时长、私下动机或谁对谁错；不得贴性格、疾病或长期关系类型标签。

## R15：健康状态覆盖身心信号但不做诊断

健康卡同时关注身体和日常心理负荷。困倦、长时间吐槽/宣泄和反复低强度信号不能被机械删除；可以分析趋势、触发、维持环路、恢复和可能关联，但不得做医疗或心理诊断、把相关写成因果，或建议擅自改处方。

## R16：内容消费与用户观点严格分离

内容消费不默认等于学习。播客、视频、节目、音乐或自动播放内容必须先与用户自身表达分离；媒体中的观点不自动成为用户观点。只要内容本身具有独立帮助价值，不得因价值筛选而静默遗漏。

## R17：灵感先发散再收敛，报告始终帮助用户

灵感卡先接住想法、理解目标并充分发散，再围绕目标收敛为关键假设和验证。所有卡的目的都是帮助用户，而不是批判用户；模型提出的扩展不得写成用户原有想法或已接受计划。

## R18：自我成长只处理当期有证据的理解

只分析当前报告期有证据支持的自我理解。一次具体强表达或多个独立事件可以成立，但不得把一次情绪、孤立观点或编造的深层故事写成成长卡。需要建议时，提供记录模板、小实验、验证问题或其他具体工具。

## R19：生活决策提供条件化的决策与执行帮助

生活决策卡是非工作现实目标的决策与执行顾问，不是待办聚合器。证据足时给直接建议；关键信息缺失时给当前最佳的条件化判断。使用选项、判断标准、权衡、待验证信息和下一步，避免空泛的 pros/cons 列表。

## R20：审核和修订只做必要变更

统一审核负责发现事实、归属、遗漏、价值、结构和帮助性问题，不重写完整报告。跨卡统筹只输出 keep/revise/merge/drop/create、去重、归属、搜索规划和待办取舍；不生成第二份完整报告。定向修订只改受影响卡，keep 卡的 Markdown 必须字节级不变。

## R21：待办只来自明确承诺

待办只来自用户已经明确决定、接受、安排或承诺的行动，以及虽由他人执行但用户有真实跟进责任或结果依赖的事项。模型或搜索建议、普通愿望、灵感、开放问题、已完成事项和无需用户跟进的他人任务不是待办。每个输入待办候选必须恰好保留为全局待办，或进入丢弃记录并说明原因。

## R22：搜索只补充外部可验证信息

搜索不能证明逐字稿内部事实、用户或他人的动机、感受、接受状态、决定、承诺、内部进度或未公开信息。外部事实必须有可回溯且全局唯一的来源；同一规范化 URL 的来源 ID 为 `sha256(canonical_url)`。所有展示的外部事实只能由实际使用的来源支持。

## R23：Markdown 与展示层的编号边界

Markdown 不重复主标题，H2–H4 不得手工带 `一、`、`二、`、`1.`、`1、`、`（一）` 等顺序编号。前端是章节编号的唯一负责方；页面卡片头已经显示标题时，Markdown H1 只用于数据提取，不在正文重复展示。表格必须保持可读，窄屏允许横向滚动。

## 共同的事实、推断与安全边界

- 普通转述必须语义忠实；只有直接引用才需要连续、准确、可核验，且不得润色、补全或拼接。
- 有事实支持、推理自然、强度相称且允许用户修正的合理判断可以保留。证据有限时缩小结论范围，指出真正会改变判断的信息缺口；不得把开放问题写成结论、把相关写成因果、把未知动机写成已知原因，或把短期状态自动写成长期趋势。
- 不补写输入没有提供的经历、身份、关系、金额、时间、决定、承诺、疾病、深层原因和他人动机；纯文本未提供的信息不推断音量、语速、表情、动作、沉默时长或现场状态。

## 提交前共同检查

确认每张保留卡有独立价值、主体归属可靠、关键事实和原话可追溯、结构与内容匹配、建议有实质载体、待办和搜索边界正确，并且用户打开卡片后能先看到最重要的信息。
