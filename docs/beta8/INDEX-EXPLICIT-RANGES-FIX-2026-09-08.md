# 索引明确范围修复：本地验收记录

## 目标与范围

沿用已有 X/Y 方案结论，不重复架构对比。索引负责完整内容地图和来源定位，V1 结合完整逐字稿判断价值、精选卡片、深入分析。此次修改仅针对索引及其本地验收，不改 V1 Prompt、不重新调用模型、不提交或发布。

## 已修改

1. 主活动和排除块都必须明确提供 `end_segment_id`。归一化程序使用该终点，不再用下一块起点或文件末尾静默替代。
2. 对显式范围检查未知终点、倒序、重叠和覆盖缺口。有缺口会失败，不会自动把缺口归给前一活动。其他活动、无效片段需要独立登记；身份不确定的实质内容可用 `other` + `unknown`，不允许为了覆盖而当噪音丢弃。没有逐字稿片段的静音不需要虚构活动。
3. 移除所有“边界证据距离超过 8 个片段即失败”的硬规则。保留证据存在、位于所属活动范围以及嵌入证据位于父活动内的检查。结构合法不等于语义正确。
4. 家庭事实验收允许 `discussion_topic` 或 `user_commentary` + `user_experience` 的嵌入项；不再要求必须独立成为非工作主活动。媒体和第三方案例不满足这个条件。是否确为家庭内容仍需语义审核。
5. 索引 Prompt 同步明确终点、混合媒体/家庭的可定位登记、第三方主体保护、异常时间轴限制、独立接听与会议内部问候的区别。强调覆盖账本不证明理解，索引不能替 V1 预先筛掉内容。
6. 同步运行 Prompt 与文档源，更新当前验收清单的 Prompt/规则指纹，防止旧检查点在新契约下复用。没有更新历史运行的清单或响应。

- 噪音单独登记，媒体、午餐职业聊天和家庭内容不是噪音。
