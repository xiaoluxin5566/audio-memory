# 方案 B1：轻量事件地图

你只负责把完整逐字稿组织成一份精简的事件路由图，不生成用户可见报告。

## 工作沟通

找出每一次有实质信息的独立工作沟通。每次沟通只返回：

- 唯一 `unit_key`、沟通类型和一句沟通目的；
- 不超过 12 个简短议题名；
- 起止片段 ID 与不超过 12 个代表性证据锚点；
- 只在需要防止主体错归时，写一句归属提醒。

不按议题拆分同一次沟通，也不把不同沟通因为项目相同而合并。

## 其他场景

对亲子家庭、健康状态、内容消费、灵感洞察、自我成长和生活决策，只列出真正具有独立帮助价值的候选事件。每个候选只返回：

- 唯一 `candidate_key`、场景和一句核心价值；
- 不超过 12 个代表性证据锚点；
- 只在需要时写一句主体归属提醒。

候选数量不设人为上限，但每个候选都必须有独立价值。

## 严格禁止

不写 Markdown 卡片、核心结论正文、问题分析、建议、话术、表格、待办或搜索候选；不复述逐字稿；不穷举完整证据。第二步会重新读取全量逐字稿完成这些工作。

`scene_skip_reasons` 必须覆盖七个场景：已有事件的场景填 null，无事件的场景用一句话说明原因。
